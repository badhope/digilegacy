# DigiLegacy 路线图：从「持有者的规划台」到「家人能执行的工具包」

> 状态：**P0–P4 的主要能力已落地；P2/P3 的内容可信度与家人独立执行仍需持续核验**。本文件包含历史规划与实施记录，数字以当前源码/门禁脚本为准。
> AI 相关能力以用户自配端点为前提：不内置 AI 服务；未配置端点时助手/Agent 不建立外部连接，也不伪装为可用。
> 当前审核注册表包含 5 个场景：平台政策、法律文书、家人说明、资产分类、继承人可读性；AI 只能预审，人工结论才可批准。
> 判断基准只有一条：**家人拿到东西后，能不能在没有任何人帮助的情况下走完全程。**
> 测试数量、功能数量、代码行数都不参与这条判断。

---

## 一、定位复核

产品自称的六段链路：

> 资产发现 → 分类登记 → 处置规划 → 法律文书 → 到期触发 → 家人执行

首屏承诺是 **「给家人留下工具包，而不是一堆谜题」**（`README.zh-CN.md:7`）。

这条承诺的主语是**家人**，不是持有者。当前产品包含 10 个前端视图（含 NotFound）、89 个 IPC 命令、152 条平台库政策，以及可导出的报告、工具包和按平台聚合的家人执行清单；家人侧仍依赖持有人提前完成导出、保管位置记录和恢复演练。

**结论：项目的主要风险不再是“有没有导出”，而是家人能否在没有持有人帮助时按清单执行。** 因此对外描述必须把“本地规划工具”和“家人可执行材料”区分开，不把本机 UI、演示站或可选联网能力说成家人侧的独立服务。

### 历史审计项与当前状态

以下问题来自早期审计，已按当前源码重新核对；不再把旧实现当成当前缺口。

1. **导出比预览少内容**：已修复。`report.rs` 统一生成平台政策、材料、难度、时长和官方链接，回归测试覆盖导出与预览字段。
2. **导出缺少继承人联系方式**：已修复。`report.rs` 的导出回归测试覆盖联系方式，同时仍拒绝未解密占位符。
3. **报告只支持中文**：已修复。`ReportLocale` 与英文导出测试覆盖 `lang="en"` 和英文文案。
4. **ZIP 权限与报告/备份不一致**：已修复。`commands.rs` 的 ZIP 写入走 `fsutil::write_private`；Unix 权限由 `fsutil.rs` 测试覆盖，Windows 依赖应用数据目录 ACL。
5. **问卷不驱动下一步**：已修复。`DiscoverView.vue` 将勾选项映射为资产大类预选并过滤平台；它仍是辅助引导，不是自动发现。
6. **`is_confirmed` 是恒定兼容字段**：统计逻辑已不再使用该死指标，`get_dashboard_stats_db` 改为计算真实规划就绪项；字段保留用于兼容旧数据，不应被文档解释为用户核对动作。
7. **“AI 接口已预留”**：已过时。当前 `ai_assist.rs`、`agent.rs` 和审核场景已实现；它们默认关闭且只在用户配置端点后连接，不提供官方托管服务。网站副本中的旧文案必须随站点内容同步更新，本轮不访问远程平台。

### 当前仍需持续核验的结构性风险

8. **完成度不是现实交付保证**：当前完成度由处置、继承人、账号标识和触发链等就绪项组成；它不代表平台受理、法律效力或实际资产价值。
9. **继承人角色与资产分配仍需人工核对**：已支持多继承人与一个执行人，但资产层的分配说明与平台/法律要求仍由用户自行确认。
10. **政策库仍有未核实条目**：本轮溯源门禁通过，但 152 条中 147 条明确标为未核实，另有 5 条有出处但缺核对日期；不能对外表述为全部政策已验证。
11. **备份导入语义已改变**：生产命令默认合并并在导入前创建快照；覆盖模式需显式选择。旧的 `import_backup_json_db` 覆盖包装仅保留给测试/兼容调用，不是命令层默认路径。

## 三、AI 应该放在哪一层

### 硬约束（门禁，不是加权项）

| 门禁 | 出处 | 判定方式 |
|---|---|---|
| G1 默认不主动联网 | `AGENTS.md:38`、`tauri.conf.json:24`、`heartbeat.rs`、`ai_assist.rs` | 未配置时不建立 heartbeat、SMTP/IMAP 或 AI 端点连接；用户启用可选功能后，连接只发往其配置的端点 |
| G2 家人侧可离线使用 | 家人不一定有网、装不了软件、看不懂英文 | 已导出的报告/执行清单/工具包是静态文件；平台办理本身仍可能需要联系平台 |
| G3 安装包体积可控 | 版本产物大小随构建变化，不在 README 固定单一数字 | 通过 CI 的 Windows installer job 验证 MSI/NSIS 产物 |
| G4 CI 不依赖真实用户服务 | `scripts/verify.sh` 与 GitHub Actions 使用本地行为测试/桩 | 不在测试中调用用户自配 AI、SMTP、IMAP 或 heartbeat 端点 |
| G5 不需长期运维模型 | 单人维护的项目 | 无自建推理服务 |
| G6 解决真实痛点 | 见第二节：断点在家人侧 | 能通过「30 分钟家人演练」验收 |

### 五个候选方案

| 方案 | 核心思路 | 优点 | 缺点 | 成本 | 适用场景 |
|---|---|---|---|---|---|
| **A 运行时 BYOK 问答** | 应用内填 OpenAI 兼容端点与 Key，持有者提问 | 能力上限最高；零运维 | 家人侧无网即失效；Key 管理、提示词注入、数据出境都要自己兜；CSP 需放宽 | 中（后端 HTTP 通道 + 沙箱 + 脱敏） | 专业用户，且只服务持有者 |
| **B 作者期 AI（生成后冻结）** | 持有者在规划阶段用 AI 生成「家人 FAQ / 人话版政策 / 执行顺序」，输出为静态内容打包进工具包 | 家人零 AI、零网络；完全不动运行时契约；可人工审校后冻结 | 内容会过时；生成质量依赖持有者审校 | 低-中（一次性生成 + 审校 UI + 打包） | **本项目的正解**：AI 只在作者期出现 |
| **C 内置本地小模型** | 打包 1.7B–4B GGUF | 离线推理；无需 Key | 安装包涨到 1–2.5GB（违反 G3）；分发与 CI 成本高 | 高 | 硬件基线稳定的产品 |
| **D 官方托管服务** | 自建账号 + 云端模型 | 体验最顺 | 直接违反 G1；数据出境；运维成本 | 最高 | 与定位不相容 |
| **E 无 LLM 的规则/决策树** | 结构化问答树 + 模板拼装 + 政策字段渲染 | 零依赖、零网络、可测性最好、确定性 | 不能处理自由表达 | 低 | 覆盖 80% 的确定性问题 |

### 打分

| 门禁 | A | B | C | D | E |
|---|---|---|---|---|---|
| G1 默认零联网 | 过（默认关） | 过 | 过 | **不过** | 过 |
| G2 家人侧离线 | **不过** | 过 | 过 | **不过** | 过 |
| G3 体积 ≤50MB | 过 | 过 | **不过** | 过 | 过 |
| G4 CI 无外网 | 勉强（需 mock） | 过 | 勉强（需模型桩） | **不过** | 过 |
| G5 无需运维模型 | 过 | 过 | **不过** | **不过** | 过 |
| G6 解决家人侧痛点 | 弱 | **强** | 中 | 中 | 中高 |

### 选定：E 作离线底座 + A 作可选持有人工具

- **E 已实施**：家人执行清单内置确定性双语 FAQ，覆盖先找谁、准备什么、如何联系平台等固定问题；家人侧不依赖模型或网络。
- **A 以受限 BYOK 形式实施**：持有人可配置 OpenAI-compatible endpoint 使用问答、流式助手和受限 Agent；默认关闭，数据通过 Rust 白名单筛选，工具无凭据/写库/任意网页能力，结果需人工核对。
- **B 仍是后续内容方向**：若未来增加作者期个性化草稿，必须人工审校后冻结到工具包；当前实现的助手/Agent 不会自动写入或发布家人材料。
- **C / D 明确不做**：不打包本地大模型，不提供官方托管 AI 服务。

**边界结论**：AI 是持有人的可选辅助工具，不是家人侧执行包的前置依赖；“无服务器/无遥测”表示项目不提供托管服务或使用统计，不表示用户启用自配端点后绝不会发生外部连接。

## 五、AI 边界（写进代码，不靠自觉）

**三条红线**

1. 不做官方托管 AI 服务、不做账号体系、不做云端推理；用户启用 BYOK 后，外部连接只发往用户配置的端点。
2. AI 不写入资产、档案、凭据或审核批准状态；问答文本可按 v7 schema 留在本地历史中。AI 不生成法律意见，不杜撰平台政策或链接；没有来源就写「未核实」。
3. 凭据（`credential_enc`）、账号标识（`account_identifier`）、继承人联系方式（`heir_contact`）永不进入任何 AI 请求。白名单在 Rust 侧实现，不依赖提示词。

**两个必须**

1. 传输必须在 Rust 层，复用 `ureq` 的 TLS/超时路径与端点协议校验，**不改 `tauri.conf.json:24` 的 CSP**。前端不直接 `fetch` 用户端点。
2. AI 生成的草稿或审核建议必须由持有人人工核对；AI 不能直接批准审核、写入用户资产或生成物发布状态。

**明确不做**

- 官方托管 AI 服务与账号体系
- 法律意见生成（责任无法承担）
- Agent 直接执行 shell、任意网页检索、自动发信或修改资产/凭据
- 任何形式的遥测或使用统计上报

## 七、不做什么

- 不做手机端（维护成本翻倍，先证明桌面版有人用）
- 不做云同步（与 no-server 冲突）
- 不做社区政策库（没有审核能力时，错误信息比没有信息更危险）
- 不做账号交易/代办理（法律与合规风险）
- 不提供官方托管 AI 服务；助手/Agent 只在用户配置端点后运行，且不作为家人侧离线工具包的运行时依赖

## 十、2026-10-30 第四轮：内置 Agent（已实施）

这一轮不是把一个聊天框改名为 Agent，而是落地了**受限自主工具循环**：Rust 端最多 8 轮、每轮最多 6 个工具；工具只读本地数据或产出草稿，不存在写资产/档案/凭据/恢复码的工具。

| 维度 | 实现 | 约束 |
|---|---|---|
| 工具协议 | OpenAI-compatible `tool_calls`，arguments 支持字符串与对象；外层 call id 原样回传 | 未知工具显式报错；调用数有上限 |
| 本地检索 | 资产规划摘要、内置政策、规划统计、家人演练、DMS 状态 | `query_assets` 不返回账号标识、继承人姓名/联系方式、备注、凭据 |
| 草稿 | `draft_heir_note` | 文本结果明示人工确认，不落库 |
| 安全 | 端点校验、API Key 非空、任务/工具参数长度与控制字符校验、结果 6000 字截断 | tool result 回传前加不可信资料标记，防 prompt injection |
| 可见性 | `AgentEvent` 通过 Tauri Channel 推送 `started/tool_start/tool_end/final/truncated` | 前端显示步骤时间线；事件不参与安全决策 |
| 降级 | 未配置端点、浏览器演示、旧后端不支持流式时明确失败或回退单轮助手 | 不伪装 Agent 可用 |

### AI 结合下一阶段

- **已完成**：助手单轮问答、SSE 流式、本地历史、四审核场景 +「继承人读得懂」Strict 场景、受限 Agent。
- **下一步**：Agent 工具调用取消（AbortController 语义）、批量审核进度回报、AI 起草「给家人的开头说明」草稿（人工确认后写入）。
- **明确不做**：Agent 直接执行 shell、任意网页爬取、自动发信、直接改数据库、绕过人工审核。这些会破坏 no-telemetry 或 AI never approves 契约。
