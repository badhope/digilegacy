# 竞品深度对照：DigiLegacy 从同类产品学到了什么

> 本文件回答两个问题：市场上有哪些同类产品、它们的哪些优点已经被本项目**落到代码里**（而不是停留在「值得借鉴」）。
> 调研基线：2026-11；产品形态分三类——托管服务（数据在别人服务器）、本地优先软件（数据在你机器上）、自托管开源。
> 判断基准与 ROADMAP 一致：**家人拿到东西后，能不能在没有任何人帮助的情况下走完全程。**

## 二、已经落进代码的借鉴点

| 来源 | 借鉴点 | 本项目落地方式 |
|---|---|---|
| 全行业 | 三级确认链（本人→紧急联系人→执行人） | DMS 三阶段通知 + 逐级等待窗口（`notify.rs`），并诚实标注「仅应用运行时评估」 |
| Inheriti / LastSignal | Shamir 秘密分片保护主密钥 | `heir_recovery.rs`：3-of-5 GF(256) 分片，Base32 纸面份额 + SHA-256 校验和（2026-11 迁移到修复了 RUSTSEC-2024-0398 的 `blahaj`） |
| KeePassXC | **可打印应急 Kit** | 可打印继承报告 + ZIP 工具包 + 家人执行清单（`report.rs`/`action_guide.rs`），全部开放格式，脱离应用可读 |
| SafeBeyond / LastSend | 送达前人工确认，防「忘了签到」误触发 | 三级链里前两级都是活人确认，不是纯计时器 |
| 多家（Switchify/GoodTrust 指南） | **外出暂停**防误触发 | `set_dms_pause`（2026-11 落地）：日期制暂停，逾期评估整体挂起，到期自动恢复——日期制而非布尔制，忘了恢复也不会让触发链一直裸奔 |
| 多家（全行业共识） | **年度复核**提醒 | `record_planning_review`（2026-11 落地）：从未复核或超 365 天，仪表板出现 info 级待办，DMS 页一键记录 |
| Everplans | 保管位置（哪把钥匙在哪）必须显式记录 | `db_custody.rs`：备份位置 + 恢复码位置，缺失时仪表板 blocker |
| Cipherwill / DeadDrops | 每项资产独立指定受益人 | 多继承人 + 执行人 + 逐资产处置方式（`db_heirs.rs`） |
| 评审类产品（Trustworthy 等） | 「组织好」只是开始，「家人会用」才是终点 | 家人演练（`toolkit::evaluate_drill`）：用元数据推演家人会在哪一步卡住 |
| LastSignal / Seppuku | 自托管 vs 托管的诚实权衡 | 本项目选择第三条路：本地优先 + 自配 SMTP，不假装自己是高可用托管服务（README「如实说明的边界」） |

## 三、明确评估过但不采用的能力（及理由）

| 能力 | 来源 | 不采用理由 |
|---|---|---|
| 云端托管密钥/载荷 | Cipherwill、GoodTrust 等 | 与「所有数据都在你自己的机器上」的核心承诺冲突；托管=别人可以关门、被收购、被传唤 |
| 受益人主动请求 + 计时否决 | AbsentKey | 需要在线服务做请求中转；本地优先架构下家人根本没有「发起请求」的入口。替代方案是打印执行清单（离线可用） |
| 区块链存证 | Inheriti | 增加不可验证的信任假设，对「家人能执行」无实际帮助 |
| 每日签到 | Snug | 个人遗产规划场景频率过低或过高都不对；30 天默认 + 可调 1-365 天已覆盖 |
| 联邦多节点 | Posthumous | 需要用户运维多台服务器，超出目标用户能力；诚实标注单机边界更符合本项目气质 |
| 每日 AI 主动建议 | Just In Case 的 AI 引导 | AI 只在用户自配端点时工作，且只能预审不能批准（审核管线硬约束） |

## 四、与竞品的差异化定位（对外表述口径）

- 竞品几乎全部要求**信任一家公司的持续存续**；本项目数据不离开本机，公司关门不影响数据可用。
- 竞品的触发器活在别人的服务器上；本项目的触发器活在你自己的机器上——代价是「机器关机不评估」，这一点所有材料都如实写明，而不是含糊其辞。
- 竞品交付「消息」；本项目交付**可执行的工具包**：逐平台材料、流程、难度、时长、官方链接 + 演练检查 + 恢复包 + 保管位置。家人拿到的是路，不是谜。
