## 这一轮修掉的细节

1. 删除确认的“取消”曾显示 `common.cancel`，中英文都已补键。
2. 删除确认条原被挤在生命周期按钮旁，改为 `flex-wrap` 后独占一行。
3. 空估值详情标题会误写“市值”；现在区分“待评估”和“未填估值”。
4. 后端局部更新原会把省略的机构、金额、备注清空；改为省略保留、显式空串清空。
5. `valueStatus=unknown` 时金额必须为空；已有数字再切待评估会清零，之后拒绝非空金额。
6. 估值拒绝负数、`NaN`、`inf`；平台、备注和列表状态都有边界校验。
7. 到期日拒绝 `2026-02-30` 这类不存在的日期。
8. 保存并继续保留类型与口径；测试断言 `financial` 与 `appraised` 不被重置。
9. 草稿只在任一文本字段有内容时保存，类型单独选择不再触发恢复。
10. 编辑资产会关闭残留的删除确认条，并清空删除错误。
11. `clean_drill.py` 的 schema 断言改为 19，干净机演练不再拿旧版本卡新包。
12. “更多字段”的符号改为 CSS 伪元素，避免为 `+ / −` 增加内联节点，压回 121 KB JS 预算。

## 测试库事故与恢复

首轮启动演示服务时误用了 `DIGILEGACY_DB_PATH`，而程序读取的是 `DIGILEGACY_DB`，因此短暂连到了真实库。发现后立即停止服务，并按创建时间、资产 id 与审计记录定位，删除 6 条演示资产、5 条平台记录、6 条对应 `asset.create` 审计，资产自增序列归零。真实库现在为 **0 资产、18 条原有审计**，原审计链末条仍为 `3c7a…`；schema 已按 0.0.34 启动迁移到 **v19**。后续复验全部使用 `/tmp/dg-ui-demo.db`。
