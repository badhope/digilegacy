# 连接配置交接说明

当邮箱、Webhook、飞书或企业微信账号属于别人时，用这份说明交接。平台方不收集账号密码，由账号本人在控制台填写并测试。

**填写入口：** `https://<你的-digilegacy-主机>/settings/connections`

同一页面顶部有“账号接入引导”，可直接选 SMTP、Webhook、飞书、企业微信，也可以复制填写说明发给对方。

## 网络前提

平台只解析一次地址，并且只连接校验通过的地址。生产部署的 `DIGILEGACY_OUTBOUND_ALLOWLIST` 必须包含服务商主机（例如 `smtp.example.com` 或 `open.feishu.cn`），否则连接测试会在 DNS 解析前被拒绝。私网端点还需要 `DIGILEGACY_ALLOW_PRIVATE_NETWORK`。出站客户端不使用环境 HTTP 代理，因此“只能经代理出网”的部署方式不适用于这些测试。

## 只需要发什么

1. 控制台地址；
2. 平台写令牌，走单独的可信渠道；
3. 下表中的账号字段。

不要把邮箱密码、授权码、Webhook secret 或令牌发到群聊、工单、截图或仓库里。

## 填写字段

| 类型 | 必填 | 说明 |
|---|---|---|
| SMTP 邮箱 | 连接地址 `host:port` | 465 通常是 **TLS**，587 通常是 **STARTTLS**；以邮箱服务商说明为准。 |
| SMTP 邮箱 | 用户名 | 一般是完整邮箱地址。 |
| SMTP 邮箱 | 凭据 | 优先用应用专用密码/授权码；普通登录密码可能被服务商拒绝。 |
| SMTP 邮箱 | 发件人 | 收件人看到的地址，必须是服务商允许的发件地址。 |
| SMTP 邮箱 | 加密方式 | `TLS`、`STARTTLS` 或 `None`；不可控网络不要选 `None`。 |
| Webhook | 完整 URL | `https://...`，不要有空格或换行。 |
| Webhook | 凭据 | 服务商要求时填 Bearer token 或签名密钥，可留空。 |
| 飞书 | 机器人 Webhook 完整 URL | 在目标群里建机器人，不要用个人会话 Webhook。 |
| 企业微信 | 机器人 Webhook 完整 URL | 同样用群机器人，不要用个人机器人。 |

## 填写人操作步骤

1. 打开控制台，进入 **设置 → 连接**。
2. 在顶部填**平台写令牌**。令牌只存在当前浏览器会话，不写本地存储。
3. 点引导里的对应按钮，或点“新增连接”选择类型。
4. 填名称、地址、凭据；SMTP 还要填用户名、发件人、加密方式。
5. 点“保存”，再点“测试”。显示绿色 **OK** 和延迟，说明平台能连到服务商；这不等于最终送达。
6. 只把连接**名称**和状态截图交回来，不要回传凭据。

## 平台保存什么

- 连接配置用服务端连接密钥加密（`DIGILEGACY_CONFIG_KEY_FILE`，或从 `DIGILEGACY_DB_KEY_FILE` 派生的域密钥）。
- Web 界面不会回显已保存的凭据；编辑时必须重新填地址和凭据。
- 服务端没有连接密钥时，保存会返回 `CONFIG_KEY_MISSING`；先让平台管理员配置密钥。
- 连接测试只验证连通性/认证；服务商“已接受”和“最终进收件箱”仍需单独演练。

## 交接检查

- [ ] 控制台地址和写令牌分开发送
- [ ] 账号本人确认服务商允许的 SMTP 端口与加密方式
- [ ] 连接已保存，名称清晰，例如 `work-mail` 或 `ops-webhook`
- [ ] 测试返回 OK
- [ ] 已收到名称与状态截图；工单里没有凭据
- [ ] 变更后检查 `security status --json` 与 `/api/v1/metrics`

测试失败时记录错误码和服务商返回，不要为了“先跑通”关闭 TLS 校验或把凭据贴进工单。
