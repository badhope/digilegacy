# 安全策略

[English](../../SECURITY.md) | 简体中文

## 报告安全问题

**不要为安全问题开公开 issue。**

请使用 GitHub 的[私密安全公告](https://github.com/badhope/digilegacy/security/advisories/new)表单。如果无法使用，可以开一个不含技术细节的公开 issue，请维护者提供私下沟通渠道。

请说明受影响的版本、平台、复现步骤和你判断的影响。我们会在收到后一周内确认。项目没有漏洞赏金。

## 支持的版本

只有最新发布版本和 `main` 分支会获得安全修复。更早的版本可以保留作参考，但不再提供支持。

## 威胁模型

DigiLegacy 是 API-first 的数字遗产平台，不是只在本地运行的桌面应用。平台负责数据、权限、审批、审计与导出；Web、CLI、MCP 和 Agent 都是入口。

### 防护范围

| 威胁 | 应对 |
|---|---|
| 数据库或备份被拿走 | 敏感字段写入前加密；密钥只在进程内存中，不进入日志或浏览器存储。 |
| 绕过应用直接打开 SQLite | 字段级认证加密；Vault 锁定时 Rust 层直接拒绝解密。 |
| 锁定后凭据泄漏 | 解密在 Rust 层失败，不靠 UI 遮罩。 |
| 密文被篡改 | 认证加密会拒绝被改动的密文。 |
| 报告或工具包泄露密钥 | 报告和工具包不包含凭据字段；导出物仅所有者可访问。 |
| HTTP、IPC 或 MCP 输入畸形 | 写入前做 schema 校验、大小限制和枚举/边界检查。 |
| Agent 自己批准自己 | 写工具必须人工审批；密钥、网络、桌面能力永不进入 Agent 或 MCP。 |
| 邮件头注入 | 头部去掉 CR/LF，SMTP 正文做 dot-stuffing。 |
| Webhook 或连接探针被滥用 | 限制请求体、显式超时、凭据脱敏、配置缺失时 fail closed。 |

### 不在防护范围

- 以同一系统用户身份运行的恶意软件。它可以读取进程内存或等到解锁。
- 已经知道主密码或恢复材料的人。
- 明文导出物。交付出去的报告就是普通文件。
- 被攻破的构建或发布流水线。请校验发布产物。

## 安全实践

- 密钥先加密再存储，读模型永不返回凭据。
- 审批和审计记录按只追加设计；被拒绝的动作不会悄悄消失。
- 生成客户端与契约一起评审，避免某个入口漏掉权限变更。
- 依赖和发布检查进入 CI；已知严重问题阻断发布。

## 保险库引导与锁定

首次设置只走本地 CLI，避免把“设置主密码”暴露成远程接口：

```bash
printf '%s\n' "$DIGILEGACY_MASTER_PASSWORD" | digilegacy security init
```

口令从标准输入读取，至少 8 个字符。命令会创建 DEK/KEK、恢复封条并写入 `security_config`；恢复码只输出这一次，应离线保存。初始化同时把已有连接凭据与政策候选密文迁移到保险库派生的域密钥，迁移失败会整体回滚。

服务进程重启后保险库默认锁定。锁定时应用层只允许 `security.status`、`security.unlock`、`security.recover`、`security.lock`，其余命令返回 `423 VAULT_LOCKED`；Web 锁屏只有在本地 API 校验口令或恢复码成功后才挂载主壳。

Web 锁屏可在主密码与恢复码之间切换。恢复码只用于解锁当前服务进程；它不会写入浏览器存储，也不会替代离线备份。`security.unlock` 与 `security.recover` 共享进程内失败限速：60 秒窗口内累计 5 次失败后锁定 30 秒，返回 `429 RATE_LIMITED`，锁定期间正确主密码同样被拒；成功解锁会清零。服务重启后限速状态清空。

CLI 每条命令都是独立进程，单独的 `security unlock` 不会把密钥带给下一条命令。已配置保险库时，交互终端会为当前命令提示输入主密码；脚本可设置 `DIGILEGACY_VAULT_PASSWORD`，命令结束后密钥随进程退出。`security recover` 从标准输入读取恢复码，同样只影响当前进程。

边界：

- 恢复码只在初始化时输出一次，应离线保存；Web 入口不改变它的一次性材料属性。
- 失败限速是进程内状态，服务重启会清空；解锁接口随 API 默认绑定回环地址。若把 API 暴露到局域网或公网，必须在反向代理再增加独立的限流与访问控制。
- `security_config` 存在后，字段加密使用会话 DEK 派生的域密钥；SQLCipher 的文件密钥仍然保留，用于整库加密。两者职责不同，不能互相替代。

## 迁移说明

安全关键行为只放在 `core/security` 和 `core/store`。不要恢复已删除的桌面应用，也不要把旧代码接进新入口。
