# 平台定位

[English](../POSITIONING.md) | 简体中文

## 一句话

**DigiLegacy 是一个 API-first 的数字遗产平台。Web 控制台是主客户端，Agent 通过工具使用同一套平台能力。**

它不是“加了一个 Agent 的本地小工具”，也不是“Agent 自带后端、Web 只负责聊天”的空壳。

## 要解决的问题

数字遗产的真实工作被拆散在资产清单、相关的人、按时间触发的释放规则、平台政策，以及家人真正需要用的文档里。多数工具只解决其中一小块，剩下的仍留在笔记或某个人的脑子里。

DigiLegacy 把这些内容收进同一份事实、同一套权限和同一个命令层。Web、CLI、MCP 与 Agent 看到的都是同一份数据。

## 面向谁

| 使用者 | 主要动作 | 主要入口 |
|---|---|---|
| 持有人与家庭 | 登记资产、指定继承人、配置释放规则、查看交付物。 | Web 控制台 |
| Agent | 读取平台、起草方案、发起需要审批的动作。 | 工具调用 / MCP |
| 运维与开发者 | 查看健康状态、发现命令、诊断问题、迁移与恢复。 | CLI / Platform API |

## 产品承诺

- **一份记录。** 资产只录入一次，列表、详情和交付报告引用同一事实。
- **改动由人控制。** Agent 可以提议，人批准后平台才执行，并记录发生了什么。
- **交付能直接用。** 家人拿到的是报告、清单、法律文本模板和可操作的工具包。
- **可审计。** 每个敏感动作都有执行者、理由和可回看的记录。
- **自托管不是另一套产品。** 本地部署只是同一种平台的运行方式。

## 边界

- 平台负责数据、权限、审批、审计和执行。
- Agent 是平台的客户端，不是并行后端。
- 写工具必须审批；密钥、网络和桌面能力永不暴露给 Agent。
- 接口契约是唯一事实源，不允许手改生成客户端。
- 没做好的功能不伪装成功；不支持的命令会明确失败。

## 成功的样子

新用户不用读说明书，就能登记一项资产、指定一位继承人，并知道下一步做什么。家人打开交付报告后知道该怎么做。运维能把任何一次变更追回到具体的人和具体命令。
