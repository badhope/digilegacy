# 平台定位

## 1. 一句话

**DigiLegacy 是一个 API-first 的数字遗产平台：Web 控制台是主客户端，Agent 通过工具驱动平台。**

不是“带 Agent 的本地小工具”，也不是“Agent 自己一套后端、Web 只是聊天壳”。

## 2. 要解决的问题

数字遗产的真实工作被拆散在：

- 资产清单：账号、文件、订阅、设备、保险、域名、社交资产。
- 人：持有人、继承人、执行人、见证人。
- 触发链：安全签到、等待期、双人确认、争议处理。
- 交付物：家庭报告、执行清单、法律文本、家人工具包。
- 运行与审计：Agent 做了什么、谁批准、何时执行、失败了怎么办。

平台的任务是把这些收进**同一份事实、同一套权限、同一条命令总线**，让 Web、Agent、CLI、MCP 看到一致的平台能力。

## 3. 三类使用者

| 使用者 | 主要动作 | 入口 |
|---|---|---|
| 持有人/家庭 | 登记资产、设置继承人与触发链、查看交付物 | Web 控制台 |
| Agent | 读取平台、生成草稿、发起待审批动作、查询运行态 | 工具调用 / MCP / Builtin Agent |
| 运维/开发者 | 健康检查、契约发现、诊断、迁移与恢复 | CLI / Platform API |

## 4. 五个主入口

1. **概览**：完成度、待办、审批、运行态。不做第二份清单。
2. **资产**：从发现到处置，每个资产只维护一份事实。
3. **规划**：持有人、继承人、触发链。
4. **交付**：报告、清单、法律文本、工具包，来自同一份数据。
5. **自动化**：Agent 运行、审批队列、工具目录、审计。

设置是全局工具区，放在右上角，不占业务导航。

## 5. 平台与 Agent 的边界

```text
Agent 提议 → 平台生成待审批 → 人批准 → 平台执行 → 审计留痕
```

- Agent 不能自批。
- `write` 工具默认 `approval=required`。
- `key` / `network` / `desktop` 永不暴露给 Agent/MCP。
- Agent 的读写都走同一命令与同一权限表，不允许“Agent 专用后门”。
- Web 和 Agent 看到同一份数据；不允许各存一份。

## 6. 明确不做

- **不把“本地运行”作为卖点**。平台主要接 API；本地只是部署形态之一。
- **不做桌面工具定位**。桌面端是可选客户端，不是平台本体。
- **不做 Agent 侧边聊天壳**。Agent 是工具调用者，不是平台外的第二套产品。
- **不为 Agent 单独写后端**。
- **不保留旧路由并做重定向**。旧应用不进入新包。
- **M0-M2 不拆微服务**。先做模块化单体，按真实热点再拆。
- **不伪造成功态**。未接入的领域命令返回 `UNSUPPORTED`，不返回假数据。

## 7. 成功标准

### 用户侧

- 5 分钟内完成一次“资产登记 → 继承人设置 → 触发链检查”。
- 任一资产能在列表、详情、交付物三处追溯到同一事实。
- Agent 的每一次写动作都能在审批队列看到 diff、理由与审计记录。

### 工程侧

- 契约改动一处，Web/CLI/HTTP/MCP/mock 同步更新。
- 新增入口不新增业务逻辑。
- 性能与加载有预算，回归可发现。
- 任何不可逆变更都有 ADR 或变更单。

## 8. 版本节奏

| 里程碑 | 目标 |
|---|---|
| M0 | 工程壳、契约、四入口、Web 壳、门禁、文档 |
| M1 | 安全内核、Vault、SQLite/SQLCipher、真实 store |
| M2 | 资产/规划/交付领域服务与 Web 真实读写 |
| M3 | Agent runtime、审批、工具执行、自动化页 |
| M4 | 集成（邮件/云盘/LLM）、触发链、演练 |
| M5 | 桌面端、导出、诊断、发布工程 |
| M6 | 硬化、性能、可访问性、合规与运营 |

详细 WBS 与模块注册表见 [v1.2 计划](plan/README.md)。
