# 04 · 接口与数据契约

> 本文件是实现的“硬边界”：命令、错误、数据库、外部协议。任何改动先改这里，再改代码。
> 性能/加载相关的分页、ETag、长任务契约见 `08 §1–§2`。

## 1. 命令契约（唯一事实源 `contracts/commands.json`）

### 1.1 命名

`domain.action`，全小写、点分隔。域固定为：

```text
app  assets  platform  plan  trigger  deliver  review  drill
security  backup  checkpoint  connections  llm  agent
policy_sync  mail  heartbeat  diagnostics  settings
```

示例：`assets.list`、`plan.heirs.set`、`trigger.checkin`、`deliver.export`、`connections.test`。

### 1.2 Manifest 结构

```json
{
  "name": "assets.list",
  "domain": "assets",
  "summary": "列出当前资产",
  "permission": "read",
  "requiresUnlock": false,
  "idempotent": true,
  "input": "assets.list.input.json",
  "output": "assets.list.output.json",
  "transports": { "ipc": true, "cli": "assets list", "http": "GET /api/v1/assets", "mcp": true, "agent": true },
  "agentApproval": "none",
  "audit": false,
  "errors": ["INVALID_ARGS", "STORE_NOT_READY", "INTERNAL"]
}
```

### 1.3 权限档

| 档 | 含义 | HTTP | CLI | MCP | Agent |
|---|---|---|---|---|---|
| `read` | 读本地数据 | 允许（只读默认） | 允许 | 允许 | 允许 |
| `draft` | 生成草稿/预览，不落业务最终态 | 允许 | 允许 | 允许 | 允许 |
| `write` | 改本地数据 | 需写权限 token | 允许（`--allow-write`） | 禁止 | **需审批** |
| `key` | 主密码/恢复/库密钥 | **永远 403** | 允许（本地） | 禁止 | **禁止** |
| `network` | 出站请求 | **永远 403** | 允许 | 禁止 | **禁止** |
| `desktop` | 窗口/托盘/自启 | 不支持 | 不支持 | 禁止 | **禁止** |

规则：Agent 工具由同一命令 manifest 生成；`write` 默认 `approval=required`，批量阈值在 `contracts/tools.json` 配置。

### 1.4 信封

```json
{
  "success": false,
  "code": "VAULT_LOCKED",
  "message": "应用已锁定，请先解锁",
  "data": null,
  "details": { "field": "credential" },
  "traceId": "01J..."
}
```

规则：
- `success=true` 时 `code=OK`；
- 业务失败返回 `success=false`，HTTP 状态按 `code` 映射（不是一律 500）；
- `message` 给用户看，`details` 给程序看；两者都不含密钥/路径/凭据；
- 同一命令在 IPC/CLI/HTTP/MCP 的字段名与类型完全一致。

## 2. 错误码（唯一事实源 `contracts/errors.json`）

| code | HTTP | 可重试 | 用户文案要点 | 触发场景 |
|---|---|---|---|---|
| `INVALID_ARGS` | 400 | 否 | 指出哪个字段、怎么改 | 缺字段/类型错/枚举未知/超长 |
| `NOT_FOUND` | 404 | 否 | 对象不存在或已删除 | 未知命令、资产 ID 不存在 |
| `CONFLICT` | 409 | 否 | 与现有数据冲突 | 重复导入、政策候选冲突 |
| `AUTH_REQUIRED` | 401 | 否 | 需要登录/token | HTTP 未带 token |
| `FORBIDDEN` | 403 | 否 | 该入口不允许此操作 | 密钥/出站命令经 HTTP |
| `VAULT_LOCKED` | 423 | 是（解锁后） | 应用已锁定 | 锁定态读敏感字段 |
| `RATE_LIMITED` | 429 | 是（退避） | 请求过于频繁 | LLM 429、解锁尝试过多 |
| `NETWORK` | 502 | 是 | 网络不可达 | DNS/连接失败 |
| `PROVIDER_AUTH` | 502 | 否 | 模型服务鉴权失败 | 401/403 |
| `PROVIDER_ERROR` | 502 | 是 | 模型服务返回错误 | 5xx/协议错 |
| `TIMEOUT` | 504 | 是 | 请求超时 | 60s 超时 |
| `IO` | 500 | 是 | 文件写入失败 | 磁盘满/权限 |
| `CORRUPT_DATA` | 500 | 否 | 数据损坏，需恢复 | 校验失败 |
| `STORE_NOT_READY` | 503 | 是 | 数据库未就绪 | 未初始化 |
| `STORE_POISONED` | 503 | 是（重启） | 数据库锁异常 | mutex 中毒 |
| `CAPACITY` | 413 | 否 | 内容超限 | 请求体过大 |
| `UNSUPPORTED` | 501 | 否 | 该入口不支持 | 桌面命令走 CLI/HTTP |
| `INTERNAL` | 500 | 是 | 未知错误，附 traceId | 兜底 |

### 2.1 CLI 退出码

| 退出码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 业务失败（`success=false`） |
| 2 | 参数错误（`INVALID_ARGS`） |
| 3 | 认证/锁定（`AUTH_REQUIRED`/`FORBIDDEN`/`VAULT_LOCKED`） |
| 4 | 网络/Provider（`NETWORK`/`PROVIDER_*`/`TIMEOUT`） |
| 5 | 内部/数据（`INTERNAL`/`CORRUPT_DATA`/`STORE_*`） |

### 2.2 Platform API 映射

- 资源路由：`GET /api/v1/<resource>`、`GET /api/v1/<resource>/{id}`。
- 资源集合：`overview`、`assets`、`platforms`、`plan`、`heirs`、`triggers`、`checkins`、`deliverables`、`reviews`、`drills`、`agents`、`tools`、`runs`、`approvals`、`workspace`、`connections`、`security`、`audit`、`events`、`jobs`。
- 写命令：`POST /api/v1/<domain>/<action>`，body 即参数对象。
- 通用命令入口：`POST /api/v1/invoke`，供脚本/Agent 使用；语义与资源路由一致。
- 不保留旧 `/api/invoke`；旧客户端必须迁移到 `/api/v1`。
- 鉴权：Web 会话 cookie + CSRF；API/Agent 用 Bearer token；同一权限矩阵。
- 版本：`/api/v1` 路径版本；破坏性变更升 `v2`，不静默改字段。
- 分页：`cursor` + `limit`；列表默认 50、最大 200；返回 `nextCursor`，不返回全量。
- 缓存：GET 支持 `ETag`/`If-None-Match`，304 不返回 body；静态资源 hash + `immutable`；敏感资源 `Cache-Control: no-store`。
- 长任务：报告/PDF/ZIP/批量导入返回 `jobId`；进度走 SSE `job.updated` 或轮询；前端不阻塞。
- 压缩：API 响应支持 gzip/br；大字段不重复传。
- 幂等：写请求支持 `Idempotency-Key`；重复键返回首次结果。
- 实时：`GET /api/v1/events` SSE；事件带 `id`，支持 `Last-Event-ID` 补发。
- 限流：`429` + `Retry-After`；Agent 工具独立配额。
- CORS：只允许配置的来源；默认同源。
- `key`/`network`/`desktop` 一律 403；非回环绑定必须带 token，否则拒绝启动。

## 3. Agent 工具契约（唯一事实源 `contracts/tools.json`）

### 3.1 Manifest

```json
{
  "name": "assets.update",
  "title": "更新资产",
  "description": "修改一个已有资产的字段，返回更新后的资产",
  "permission": "write",
  "approval": "required",
  "input_schema": "schemas/assets.update.input.json",
  "output_schema": "schemas/assets.update.output.json",
  "idempotent": false,
  "audit": true,
  "human_equivalent": "assets.update",
  "available_to": ["builtin", "external"],
  "rate_limit": "30/min",
  "bulk_threshold": 10
}
```

规则：

- 工具名默认等于命令名；需要不同语义时在 `tools.json` 显式映射，不允许前端/Agent 各记一套。
- 工具只能引用已有命令，不得新增业务语义。
- `permission=draft` 只产出草稿/预览，不写最终业务态；可自动执行。
- `permission=key|network|desktop` 的工具永不进入 Agent/MCP 列表。
- `permission=write` 默认 `approval=required`；批量超过 `bulk_threshold` 必须审批。
- `available_to` 控制内置 Agent / 外部 Agent / MCP；默认只给内置。
- `audit=true` 时每次调用写审计事件，含 runId、tool、对象、结果、耗时。

### 3.2 审批与运行

| 概念 | 规则 |
|---|---|
| Run | `queued→running→waiting_approval→running→succeeded/failed/cancelled` |
| Approval | `pending→approved/rejected/expired`；拒绝必填理由；过期需重发 |
| 审批展示 | 工具、对象、diff、影响条数、可回滚点、预计成本 |
| 审批人 | 持有人/平台管理员；Agent 不能自批 |
| 取消 | 下一轮工具调用前生效；已发出的只读请求不强行中断 |
| 预算 | 每 Run 轮次 ≤8、每轮工具 ≤6、token/成本上限；超限终止 |

### 3.3 事件

```json
{ "id": "evt_...", "type": "run.step", "runId": "run_...", "step": 2, "title": "检查资产完整性" }
{ "id": "evt_...", "type": "tool.called", "runId": "run_...", "tool": "assets.list", "permission": "read" }
{ "id": "evt_...", "type": "approval.requested", "runId": "run_...", "approvalId": "apr_...", "summary": "将修改 3 个资产", "diff": "..." }
{ "id": "evt_...", "type": "entity.changed", "entity": "asset", "id": "ast_...", "revision": 12 }
{ "id": "evt_...", "type": "run.completed", "runId": "run_...", "status": "succeeded", "tokens": 1200, "cost": 0.03 }
{ "id": "evt_...", "type": "job.updated", "jobId": "job_...", "kind": "export", "status": "running", "progress": 0.6 }
```

事件只带摘要与引用，不推凭据/明文；前端按实体键失效，不整页刷新。

## 5. 外部 Provider 契约

### 5.1 LLM（OpenAI 兼容）

- `POST {endpoint}/chat/completions`
- Header：`Authorization: Bearer <key>`、`Content-Type: application/json`
- Body：`model`、`messages`、`stream`、`tools`（可选）、`temperature`、`max_tokens`
- 响应：`choices[0].message.content` / `tool_calls`；`usage` 记录到 `llm_usage`
- 流式：`data: {...}` 行；`[DONE]` 结束；注释行与解析失败跳过；不消费 `[DONE]` 之后
- 端点：仅 `https://`；`http://` 仅允许 `localhost`/`127.0.0.1`
- 网络：60s 超时、0 重定向、失败重试 ≤2（429/5xx，指数退避）
- 禁止：把凭据/账号/姓名/联系方式/金额放入 messages（白名单构造）

### 5.2 政策数据 API

```http
GET /v1/policies?since=<cursor>&platform_id=<id>
Authorization: Bearer <key>
If-None-Match: <etag>
```

响应：
```json
{
  "version": "2026-11-01",
  "cursor": "next-cursor",
  "items": [{
    "platform_id": 16,
    "name": "B站(bilibili)",
    "category": "音视频",
    "inheritable": true,
    "required_documents": "...",
    "process_description": "...",
    "estimated_difficulty": "中等",
    "estimated_time_days": "7-30",
    "official_policy_url": "https://...",
    "source_url": "https://...",
    "verified_at": "2026-10-01",
    "evidence_hash": "sha256:...",
    "updated_at": "2026-10-01"
  }],
  "signature": "hmac-sha256:..."
}
```

规则：
- 客户端校验 `signature`（若配置了公钥/共享密钥）与 `evidence_hash`；
- 永不自动落库；一律写 `policy_candidates`；
- 同一平台同一版本重复拉取不重复入队；
- 冲突（本地已人工修改）→ `conflict`，转人工。

### 5.3 SMTP

- 465：隐式 TLS；587/其他：STARTTLS；`allow_insecure` 仅限 localhost 与开发构建。
- 20s 超时；失败降级本地发件箱，不阻断保存。
- 发件人/收件人地址解析失败 → `INVALID_ARGS`。
- 测试发送与正式发送共用同一构建器。

### 5.4 IMAP

- TLS 必须；只读 `UNSEEN` 与发件人，不读正文；仅用于“回信=我还安好”。
- 发件人白名单；去重写 `imap_seen`；失败不影响其他轮次。

### 5.5 心跳

```http
POST {endpoint}/heartbeat
{"token":"..."}
```

- 零内容；不携带任何资产/档案/凭据；
- 8s 超时；失败本地记录，不阻断；
- 参考服务端 `POST /heartbeat`、`GET /check`（Bearer 管理令牌）、`GET /health`。

## 6. 备份与导出格式

### 6.1 备份 v6

```json
{
  "format": "digilegacy-backup",
  "version": 6,
  "schema": 9,
  "app_version": "1.0.0",
  "created_at": "2026-11-19T10:00:00+08:00",
  "crypto": {
    "kdf": "argon2id|pbkdf2",
    "salt": "v3.19456.2.1....",
    "wrapped_dek": "...",
    "verifier": "..."
  },
  "payload": { "tables": { ... } },
  "checksum": "sha256:...",
  "auth": "aead:..."
}
```

- 导入必须校验：格式/版本/schema/checksum/结构；加密备份还需源口令、包裹密钥、校验器、AEAD 标签全部匹配；明文备份需显式警告“未加密”。
- `merge` 非破坏；`replace` 先写 `pre-restore` 快照。
- 导入成功写审计与 `deliverable_exports`?（备份单独记录）。

### 6.2 导出物

| 类型 | 格式 | 约束 |
|---|---|---|
| 报告 | 自包含 HTML（可选 PDF） | 无外部资源；CSP `default-src 'none'`；所有文本转义 |
| 家人清单 | 自包含 HTML | 按平台聚合；含材料/流程/时长/难度/链接 |
| 法律文书 | HTML/PDF | 模板版本；免责声明 |
| 工具包 | ZIP | `manifest.json` + 文件；路径安全；含哈希 |
| 恢复包 | HTML/PDF | 份额、步骤、校验说明；不含元数据明文 |

### 6.3 文件写入

- 统一 `fsutil::write_private`：Unix 0600；Windows 依赖应用目录 ACL + 显式权限检查。
- 文件名：`digilegacy-<kind>-<yyyyMMdd-HHmmss>-<locale>.<ext>`。
- 导出后写 `deliverable_exports`，含模板版本与哈希。

## 7. 数据分级与控制

| 级别 | 数据 | 控制 |
|---|---|---|
| **绝密** | 主密码、DEK、恢复份额、API Key、SMTP/IMAP 密码、凭据 | 只进加密字段；不落日志/不出口/不进诊断包 |
| **敏感 PII** | 姓名、电话、邮箱、账号标识、继承人信息 | 默认打码；仅白名单字段可出境；导出需用户动作 |
| **内部** | 资产数量、估值、备注、处置方式 | 本地存储；HTTP 只读模式可见（需 token） |
| **公开** | 平台政策文本、法律模板 | 可导出、可展示；仍需标来源 |

## 8. 审计事件

必须写审计的 `kind`：

```text
vault.set_master / vault.unlock / vault.lock / vault.change_master
vault.recovery_generate / vault.recovery_use
db.encrypt_enable / db.encrypt_disable
backup.create / backup.import / backup.restore / checkpoint.create / checkpoint.restore
asset.create / asset.update / asset.delete / asset.archive
deliver.export / deliver.print
connection.upsert / connection.test / connection.disable
policy.candidate.approve / policy.candidate.reject
review.decide
agent.run / agent.cancel
settings.update
```

审计链：`hash = sha256(prev_hash + canonical_json(event))`；提供“校验审计链”按钮。

## 9. 契约测试（必须存在）

1. `commands.json` ↔ Rust 注册表 ↔ TS 类型 ↔ CLI ↔ HTTP ↔ MCP ↔ mock ↔ `tools.json`：集合一致。
