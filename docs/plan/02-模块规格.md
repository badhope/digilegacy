# 02 · 模块规格

> 本文件定义“模块做完的标准”。页面布局与交互细节在 `03`；接口字段与错误码在 `04`。

## 1. 通用 Definition of Done（所有模块必须满足）

| # | 项目 | 要求 |
|---|---|---|
| 1 | 规格 | 本文件有该模块条目；接口、状态、失败模式、验收齐全 |
| 2 | 正常路径 | 主流程可用，且有至少 1 条端到端用户路径 |
| 3 | 状态完整 | 空 / 加载 / 失败 / 锁定 / 离线 / 无权限 / 部分成功，全部有明确界面与文案 |
| 4 | 输入边界 | 长度、枚举、范围、格式在边界层校验；拒绝时给可操作的原因 |
| 5 | 安全 | 敏感字段不出境、不落日志；错误不泄露密钥/路径/凭据 |
| 6 | 双语文案 | 中英键集完全相等；无硬编码中文；`<html lang>` 跟随切换 |
| 7 | 可访问性 | 键盘可达、焦点可见、标签完整、对比度 AA、尊重减少动效 |
| 8 | 测试 | 单元 + 契约 + 至少 1 条用户路径 E2E；关键算法有边界测试 |
| 9 | 性能 | 达到 `05`/`08` 预算；无 N+1、无全表扫描；分页/虚拟列表 |
| 10 | 可观测 | 错误带错误码；敏感操作写审计；诊断包能定位问题 |
| 11 | 文档 | 开发者文档（接口/边界）+ 用户帮助（该功能怎么用） |
| 12 | 无占位 | 不含 TODO/FIXME/“即将上线”；未完成项必须在缺口台账 |
| 13 | 兼容 | 迁移/备份/旧格式有测试；失败可回退 |
| 14 | 审计 | 新增数据表/命令/连接类型已更新 `01` 与 `04` |
| 15 | 加载 | 首屏/路由/查询/长任务符合 `08 §2`；无全页阻塞、CLS ≤0.1 |
| 16 | 边界 | 不跨域访问 repo；无循环依赖；架构测试通过 |

## 2. Foundation

### FND-01 应用生命周期

**职责**：平台进程启动/关闭、健康检查、后台调度器（30 分钟一轮）；不提供桌面壳；窗口/托盘/单实例不在平台范围内。
**最大作用**：后台调度器是“到期触发”的心脏，必须能在单轮 panic 后继续。
**接口**：`start()`, `schedule_round()`, `shutdown()`。
**失败模式**：重复启动 → 端口占用/健康检查失败并退出；调度轮 panic → 记录并继续；休眠唤醒 → 立即补跑一轮。
**验收**：
- 单进程内只有一条调度循环；不存在第二套桌面进程，不重复发信；
- 单轮注入 panic 后下一轮仍执行（有测试）；
- 调度器可暂停/恢复，状态进 `/api/v1/overview`；
- 退出前关闭 DB 连接并 flush 检查点。

### FND-03 命令总线

**职责**：命令注册、权限分档、参数校验、信封、跨入口分发。
**最大作用**：让 Web 控制台、Agent、CLI、HTTP、MCP 共享一套行为，杜绝“CLI 能删、界面删不掉”。
**接口**：`CommandBus::call(name, args) -> Envelope<T>`；权限档 `Read / Draft / Write / KeyLifecycle / Network / Desktop`。
**失败模式**：未知命令 → `NOT_FOUND`；参数错 → `INVALID_ARGS`；入口不支持 → `UNSUPPORTED`；未解锁 → `VAULT_LOCKED`；无权限 → `FORBIDDEN`。
**验收**：
- 七方（IPC/dispatch/CLI/HTTP/MCP/mock/tools）命令集合差集 = 显式白名单；
- 同一命令在 CLI 与 HTTP 的 JSON 信封字段一致；
- 参数错误永不映射为 500；
- 权限矩阵有表驱动测试。

### FND-04 契约与代码生成

**职责**：`contracts/commands.json`、`errors.json`、`openapi.json`、`tools.json`、`schemas/*.json` 为唯一源，生成 Rust 枚举/校验器、TS 客户端、CLI 帮助、HTTP 路由表、MCP 工具定义、Agent Tool Registry、mock 桩。
**最大作用**：把“七方漂移”变成编译期/CI 期错误。
**验收**：
- 改一条命令，七方桩自动更新；
- 生成器幂等，重复运行无 diff；
- CI 有 `contracts:check`，手改生成物直接红。

## 3. Security

### SEC-01 加密与保险库

**职责**：KDF（Argon2id v3 / PBKDF2 只读兼容）、AES-256-GCM、DEK/KEK、HKDF 域分离、锁定态、闲置自动锁定。
**最大作用**：改密 O(1)、恢复份额不因改密失效。
**接口**：`unlock(password)`, `lock()`, `status()`, `encrypt_field`, `decrypt_field`, `derive_domain(domain)`。
**失败模式**：错误密码 → 统一“密码或恢复码不正确”且限速；锁定态写 → `VAULT_LOCKED`；DEK 不匹配 → 拒绝进入而非清空数据。
**验收**：
- 改密不触碰任何密文（有测试断言 ciphertext 不变）；
- 域分离互斥（field/backup/kit 三域不可互解）；
- `Zeroizing` 全覆盖；锁定后进程内无 DEK 副本；
- 1000 条资产解锁 < 300 ms（参考机）。

### SEC-03 恢复与 Shamir

**职责**：24 位恢复码、3-of-5 份额、可打印恢复包、跨机恢复。
**最大作用**：持有人失能后家人仍能开库，这是产品不能被替代的部分。
**接口**：`create_recovery()`, `reset_with_code()`, `generate_shares()`, `recover_with_shares()`。
**失败模式**：份额不足/重复/损坏 → 明确错误；恢复码错误 → 限速；恢复包缺备份 → 提示先导出备份。
**验收**：
- 3 份恢复、5 份恢复、跨机恢复三条路径全绿；
- 恢复后字段可读、报告可导出；
- 恢复包打印版包含步骤、份额、校验说明；
- 演练模式只读、不改数据。

### SEC-04 备份与检查点

**职责**：日备份（7 天保留）、命名检查点、认证式导入（merge/replace）、pre-restore 快照、校验和。
**最大作用**：任何误操作都可撤销；家人的恢复材料可信。
**接口**：`backup::daily()`, `checkpoint::create/restore/delete`, `import::verify/apply`。
**失败模式**：磁盘满 → 不阻断启动，记录并提示；导入认证失败 → 不动现有库；替换失败 → 自动回滚。
**验收**：
- 篡改密文/校验器/包裹密钥任一 → 拒绝导入；
- merge 不删数据；replace 先写快照；
- 回滚后可再次回滚；
- 备份文件 0600，格式含版本/schema/哈希。

## 4. Store

### STO-01 连接与 schema

**职责**：单写连接 + 只读连接、WAL、busy_timeout=5000、外键、完整性检查。
**最大作用**：报告生成不阻塞列表读取；锁中毒不 panic。
**接口**：`Store::open(path, key)`, `Store::read()`, `Store::integrity_check()`。
**失败模式**：未初始化 → `STORE_NOT_READY`；锁中毒 → `STORE_POISONED`；磁盘只读 → 明确提示。
**验收**：
- 并发读+写不出现 `database is locked`（压力测试）；
- 锁中毒后所有命令返回错误码，不 panic；
- 启动时 `integrity_check` 快速版通过，失败给修复入口。

### STO-02 迁移

**职责**：`schema_migrations(version, name, checksum, applied_at)`；顺序迁移；幂等；失败回滚；旧备份导入适配。
**最大作用**：升级不丢数据，旧用户可迁入。
**接口**：`migrate::run(conn)`, `legacy::import_backup(json)`。
**失败模式**：校验和不匹配 → 拒绝启动并给恢复建议；迁移中断 → 事务回滚 + 备份保留。
**验收**：
- 每个版本有“旧库样本 → 新库”测试；
- 迁移重复执行无副作用；
- 0.6.0 备份（v5）可导入并映射到 `connections`；
- 迁移前自动备份可回滚。

## 5. Domains

### DOM-01 资产

**职责**：资产 CRUD、枚举校验、处置规则、凭据读写、批量导入导出、归档。
**最大作用**：所有后续交付物都从这里长出来；字段必须完整、状态必须可解释。
**接口**：`assets.list/get/create/update/delete/archive/import/export`。
**失败模式**：未知类别/处置 → `INVALID_ARGS`；继承无继承人 → 拒绝；锁定态读凭据 → `VAULT_LOCKED`；重复资产 → 提示合并而非静默覆盖。
**验收**：
- 六种处置方式全部有 UI 与规则测试；
- 1000 条列表首屏 < 200 ms；
- 批量导入有预览、错误行报告、部分成功；
- 凭据读取永不返回空串；
- 删除有二次确认与审计事件。

### DOM-02 平台政策

**职责**：152 条查询、16 分类、溯源状态、补丁导入、候选批准、政策版本。
**最大作用**：产品内容资产；API 同步与人工审核都落在这里。
**接口**：`policy.list/get/search/provenance/approve_candidate/patch`。
**失败模式**：无来源 → 允许但标记 `unverified`；候选冲突 → `conflict` 转人工；补丁格式错 → 拒绝且不动现库。
**验收**：
- 每条政策有 `provenance`（来源/日期/核对人/哈希/状态）；
- 未核实棘轮门禁生效；
- 候选批准后写审计、更新报告；
- 152 条查询 < 50 ms。

### DOM-03 规划

**职责**：持有人档案、紧急联系人、继承人、执行人唯一性、完成度计算。
**最大作用**：把“资产”升级为“可执行计划”。
**接口**：`plan.profile.get/set`, `plan.heirs.list/set`, `plan.completion()`。
**失败模式**：两个执行人 → 拒绝；继承份额和 ≠ 100% → 警告不阻断；缺联系方式 → 标记风险。
**验收**：
- 完成度四维口径与报告一致；
- 执行人唯一性有测试；
- 档案变更触发报告重算提示。

### DOM-04 触发

**职责**：DMS 配置、阶段评估、签到、暂停、发件箱、通知降级、计划任务保底。
**最大作用**：六段链路里唯一“无人值守”的一段；可靠性是产品承诺。
**接口**：`trigger.status/config/checkin/pause/evaluate/outbox`。
**失败模式**：无 SMTP → 本地发件箱 + 明确警告；应用未运行 → 计划任务补跑；重复投递 → 阶段幂等。
**验收**：
- 三阶段各只投递一次（有测试）；
- 签到复位；暂停到期自动恢复；
- 计划任务在应用未启动时能评估一次；
- 发件箱可查看、重试、导出。

### DOM-05 交付

**职责**：报告、家人清单、法律文书、工具包、FAQ、恢复包。
**最大作用**：产品承诺的最终形态；必须“家人能照着做”。
**接口**：`deliver.preview/export(kind, locale)`, `deliver.toolkit()`。
**失败模式**：含占位符 → 拒绝生成；模板版本缺失 → 拒绝；写盘失败 → 保留内存结果并提示路径。
**验收**：
- 每类交付物有模板版本与哈希；
- 中英双语、打印样式、自包含；
- 1000 资产报告 < 2 秒；
- 清单按平台聚合、每平台有材料/流程/时长/难度/链接；
- 导出后可脱离应用打开。

### DOM-06 审核

**职责**：五场景（政策/法律/家人说明/资产分类/继承人可读性）管线；AI 预审 + 人工终审。
**最大作用**：把“内容可信”变成可审计流程。
**接口**：`review.profiles/items/decide/progress`。
**失败模式**：AI 未配置 → 只显示人工队列；严格场景拒绝无理由 → 拒绝；未知场景 → 不静默回退。
**验收**：
- 五场景全部可列出条目；
- AI 建议与人工结论分开存储；
- 严格场景理由必填；
- 审核结果进入交付物前可阻断。

### DOM-07 演练

**职责**：家人视角走查、卡点记录、结果持久化、改进建议。
**最大作用**：唯一能验证“家人真的能执行”的机制。
**接口**：`drill.run(input)`, `drill.history()`。
**失败模式**：未解锁 → 拒绝；未完成规划 → 允许但标注“非完整演练”；中断 → 保存草稿。
**验收**：
- 演练不读取真实凭据；
- 结果含平台数、卡点、建议；
- 历史可对比两次演练；
- 演练完成率可在概览看到。

## 6. Integrations

### INT-01 连接注册表

**职责**：LLM/政策/SMTP/IMAP/心跳统一配置、密钥加密、启停、健康检查、状态机。
**最大作用**：把散落在 ProfileView 的 4 套配置收成一处；未来加 provider 不改页面。
**接口**：`connections.list/get/upsert/test/enable/disable`。
**失败模式**：配置无效 → `INVALID_ARGS`；密钥解密失败 → `VAULT_LOCKED`；测试失败 → 保存但标 `error`（不阻断保存）。
**验收**：
- 旧 4 张配置表可迁移；
- 每种连接有“测试连接”与最近错误；
- 密钥永不出现在日志/响应；
- 连接状态在设置页与相关功能页一致。

### INT-02 LLM 客户端

**职责**：OpenAI 兼容 `/chat/completions`、同步/流式、超时 60s、无重定向、HTTPS-only（localhost 例外）、错误映射。
**最大作用**：助手、Agent、审核预审三处共用一套，不再三份实现。
**接口**：`llm.chat(req)`, `llm.stream(req, on_delta)`, `llm.models()`。
**失败模式**：401 → `PROVIDER_AUTH`；429 → `RATE_LIMITED` + 退避；5xx → `PROVIDER_ERROR`；超时 → `TIMEOUT`；HTTP 明文非 localhost → `INVALID_ARGS`。
**验收**：
- 三处调用只走这一个客户端；
- SSE 解析 `[DONE]` 后不消费、注释行跳过；
- 取消能中断流；
- 请求/响应有本地用量记录（token/耗时，不含内容全文）。

### INT-03 Agent 运行时与工具注册表

**职责**：Tool Registry（manifest/权限/审批策略）、工具循环 ≤8 轮、每轮 ≤6 调用、写操作审批、取消、预算、运行记录与审计。
**最大作用**：让 Agent 能驱动平台完成真实任务，但每次写操作都要人批准、每次调用都可追溯。
**接口**：`agent.run(task, on_event)`, `agent.cancel()`, `tools.list()`, `approvals.decide()`。
**失败模式**：无端点 → fail-fast；工具未知 → 拒绝；超预算 → 收敛并说明；取消 → 当前轮结束后停；未批准写操作 → 拒绝执行。
**验收**：
- `key/network/desktop` 工具永不进入 Agent/MCP 列表（测试断言）；
- 所有 `write` 工具默认 `approval=required`，无自动批准路径；
- 每轮工具结果截断 6k；
- 取消在 1 轮内生效；
- 运行审计可查、可清；拒绝审批必须填理由。

### INT-04 政策同步

**职责**：`GET /v1/policies?since=`、ETag/游标、diff、候选入队、冲突。
**最大作用**：解决 152 条内容维护的最大成本，同时不放弃人工批准。
**接口**：`policy_sync.pull()`, `policy_sync.candidates()`, `policy_sync.approve()`。
**失败模式**：无连接 → 手动模式；签名/哈希不匹配 → 拒绝候选；diff 冲突 → `conflict`。
**验收**：
- 拉取幂等；重复拉取不重复入队；
- 候选含来源、时间、diff、哈希；
- 批准前不改变现库；
- 离线时本地政策仍可用。

## 7. Render

### RND-01 文档外壳

**职责**：HTML 骨架、CSS 令牌、`escape_html`、页眉页脚、打印规则、字体回退。
**最大作用**：三种交付物共用一套样式与转义，消灭三套 `<style>` 漂移。
**接口**：`doc::shell(title, locale, body)`, `doc::escape(s)`。
**验收**：
- 所有用户/DB 文本经转义（有 fuzz/单测）；
- 打印 A4 边距正确、无分页断裂；
- 中英字体回退正确；
- 输出自包含，无外部资源依赖。

## 8. Interfaces

### IFC-02/03/04 CLI / HTTP / MCP

**职责**：三个非 GUI 入口复用命令总线。
**最大作用**：让“无界面核对/备份/导出”与桌面完全同源。
**验收**：
- CLI 每个子命令有 `--json` 与人类可读两种输出；
- HTTP 默认只读、无 token 非回环拒绝启动、密钥/出站命令 403；
- MCP 只暴露 Read/Draft 工具，未知工具返回 `isError`；
- 三入口对同一命令的返回结构与桌面一致（契约测试）。

## 9. Web

### WEB-01 设计系统

**职责**：令牌（颜色/字号/间距/阴影/动效）、基础组件、暗色主题、减少动效。
**最大作用**：页面不再各写 CSS；一处改，全站改。
**验收**：
- 单层 CSS，无重复选择器；
- 所有字号走 `--text-*`；
- 对比度 AA（自动化检查）；
- 键盘焦点可见；
- 暗色不是反色，而是独立令牌。

### WEB-09 Agent 工作台与全局抽屉

**职责**：全局唤起、流式、Run 时间线、工具目录、审批队列、历史、payload 预览、取消、成本提示。
**最大作用**：Agent 从“报告页的附属聊天”变成平台一等公民：既能随手问答，也能管理长任务与审批。
**验收**：
- 任意页面 `⌘J` 或按钮可开；
- 流式失败自动回退非流式；
- 锁定态禁止发起；
- 出境字段预览与实际请求一致；
- 取消在 1 轮内生效；
- 写操作显示“等待批准”，批准前不落库；
- 抽屉与 `/automation/approvals` 状态一致；
- Run 时间线 500 事件 ≤300ms；取消 ≤1 轮。

### WEB-10/11 命令客户端与 i18n

**职责**：Platform API/mock 判定、生成客户端、信封、错误映射；i18n 加载、回退、类型。
**验收**：
- 生产构建不含 mock 分块；
- 前端无手写 URL/命令；
- HTTP 信封与 Agent 工具返回一致；
- `t()` 只接受已知键（类型生成）；
- 缺键 CI 失败，不在界面显示键名。

## 12. 模块“发挥最大作用”的判定

每个模块必须回答三个问题，答不上就不算完成：

1. **它替用户消除了什么不确定性？**（例：政策模块消除“这条规则是否可信”）
2. **它失败时用户会误以为什么？**（例：心跳失败若静默，用户以为家人会收到通知）
3. **它让哪个下游模块能少做一件事？**（例：连接注册表让设置页不再各写一套配置）

答案写在模块的 PR/验收记录里，不写在代码注释里。
