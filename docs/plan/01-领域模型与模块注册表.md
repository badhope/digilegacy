# 01 · 领域模型与模块注册表

> 依赖规则见 `00-总纲.md §5.2`；本文件只定义“有哪些东西、它们必须满足什么、由哪些模块负责”。

## 1. 领域实体

| 实体 | 关键字段 | 说明 |
|---|---|---|
| **Workspace（工作区）** | `id`, `name`, `plan`, `created_at` | 平台边界；本期单工作区，保留 `workspace_id` 供后续多租户 |
| **Vault（保险库）** | `state`, `kdf_params`, `wrapped_dek`, `verifier`, `recovery_seal` | 主密码、DEK、恢复条件；状态为未配置/锁定/解锁 |
| **Profile（持有人档案）** | 姓名、出生、联系方式、紧急联系人、主继承人 | 报告与通知的抬头 |
| **Heir（继承人）** | 姓名、关系、电话、邮箱、份额说明、是否执行人 | 可多个；执行人最多一个 |
| **Asset（数字资产）** | 平台、类别（财产/人格/混合）、账号标识、估值、凭据、处置方式、继承人、备注、状态 | 核心业务对象；凭据加密 |
| **Platform（平台政策）** | 152 条：继承性、材料、流程、难度、时长、官方链接、变现路径、风险、标签 | 内容资产；带溯源 |
| **PolicyProvenance（政策溯源）** | 来源 URL、核对日期、核对人、证据哈希、状态 | 每条政策一份；未核实是合法状态 |
| **PolicyCandidate（政策候选）** | 平台、来源、拉取时间、原始载荷、diff、状态 | API 拉取后进入人工审核 |
| **Connection（连接）** | 类型（LLM/政策/SMTP/IMAP/心跳）、配置密文、启用、最近检查、状态、错误 | 所有外部能力的统一配置 |
| **TriggerConfig（触发配置）** | 启用、间隔、三级收件人、通道、暂停到期日 | DMS |
| **CheckIn（签到）** | 时间、来源（应用/托盘/邮件/API） | 复位触发链 |
| **ReviewItem（审核项）** | 场景、对象键、指纹、状态、AI 建议、人工结论、理由 | 五类场景共用管线 |
| **Deliverable（交付物）** | 类型、语言、生成时间、模板版本、文件哈希、状态 | 报告/清单/法律/工具包/恢复包 |
| **Checkpoint（检查点）** | 名称、时间、加密载荷、校验和 | 手动快照，可回滚 |
| **Backup（备份）** | 版本、schema、时间、校验和、认证标签 | 日备份与手动导出 |
| **AuditEvent（审计事件）** | 时间、类型、主体、对象、结果、前序哈希、本事件哈希 | 防篡改链；本地保存 |
| **DrillRun（演练）** | 开始/结束、结果、卡点、备注 | 家人演练记录 |
| **Tool（Agent 工具）** | `name`, `permission`, `approval`, `input/output schema`, `available_to` | 由 `contracts/tools.json` 生成；与命令同名 |
| **Approval（审批）** | `run_id`, `tool`, `object_key`, `diff`, `status`, `reason` | Agent 写操作的人工批准记录 |
| **Job（异步任务）** | `id`, `kind`, `status`, `progress`, `result`, `error`, 时间戳 | 导出/导入/报告/备份/政策同步的长任务；不承载业务规则 |
| **ChatLog / AgentRun** | 问题/回答、模型、轮次、工具、结果 | AI 留痕；可清除 |

## 2. 不变量（实现必须守住）

| ID | 不变量 | 违反后的后果 |
|---|---|---|
| I-01 | 锁定态禁止解密；凭据读取返回错误，不返回空串 | 空串与“从未保存”无法区分 |
| I-02 | 已配置保险库且锁定时，敏感字段禁止明文落库 | 用户以为加密，实际明文 |
| I-03 | 处置方式为“继承”时，必须指定继承人 | 家人拿到无法执行的清单 |
| I-04 | 报告/工具包含未解密占位符时，拒绝生成或导出 | 交付一份“需解锁”的废纸 |
| I-05 | HTTP 入口永不暴露密钥生命周期与出站命令 | 端口可达即密钥可换/数据可外发 |
| I-06 | AI 出境只走白名单构造；凭据、账号、姓名、联系方式、金额不出境 | 隐私泄露 |
| I-07 | Agent 工具只有 Read / Draft，没有写路径 | 模型可篡改规划 |
| I-08 | 加密备份导入必须认证：源口令、包裹密钥、校验器、AEAD 标签全部匹配；明文备份必须校验 checksum、schema 与结构，并显式警告 | 篡改/伪造备份被接受 |
| I-09 | 导入默认非破坏合并；替换模式先写导入前快照 | 一次误操作丢全部数据 |
| I-10 | schema 版本单调递增；迁移幂等；迁移前自动备份 | 升级失败无法回退 |
| I-11 | 每条政策必须有来源或显式“未核实”；未核实数只降不升 | 内容可信度腐烂 |
| I-12 | 命令契约七方一致：IPC / dispatch / CLI / HTTP / MCP / mock / tools | 一端能做的事另一端静默失败 |
| I-13 | 导出物是开放格式（HTML/JSON/ZIP/PDF），脱离应用可读 | 家人被锁死在应用里 |
| I-14 | 任何敏感操作（解锁、改密、导出、恢复、连接变更）写审计事件 | 事后无法追溯 |
| I-15 | 任何外部连接失败必须降级并显式告知，不得假装成功 | 用户以为家人会收到通知 |
| I-16 | Agent 与人类同权限：工具清单不得出现人类没有的能力；`key`/`network`/`desktop` 永不暴露给 Agent | Agent 成为提权通道 |
| I-17 | Agent 写操作必须人工审批并写审计；禁止自动批准 | 模型静默改数据 |
| I-18 | 页面、Agent、CLI、MCP 共用同一 CommandBus；禁止第二套业务规则 | 一端能做的事另一端静默失败 |
| I-19 | 前端不得直接访问 SQLite/文件系统/密钥；只能走 Platform API | 权限与审计被绕过 |

## 3. 状态机

### 3.1 保险库

```text
unconfigured ──设置主密码──► unlocked ──闲置10分钟/手动──► locked
                                  ▲                         │
                                  └──────解锁（密码/恢复）────┘
```

规则：`locked` 时所有读敏感字段返回错误；`unconfigured` 时敏感字段可明文（首次迁移路径），但首次设置主密码即全量收编。

### 3.2 触发链（DMS）

```text
stage 0 正常 ──超过间隔未签到──► stage 1 通知本人
stage 1 ──再超期──► stage 2 通知紧急联系人
stage 2 ──再超期──► stage 3 通知执行人
任意阶段 ──签到/暂停──► stage 0（暂停到期自动恢复）
```

规则：每一阶段只投递一次；无 SMTP 配置时写本地发件箱并显式标注“未送达”。

### 3.3 审核

```text
pending ──AI 预审──► ai_reviewed ──人工──► approved
                                   ├──► rejected
                                   └──► needs_changes ──修改后──► pending
```

规则：AI 永远不能到达 `approved`；严格场景（政策/法律/家人可读性）拒绝时必须填理由。

### 3.4 连接

```text
unconfigured ──保存配置──► checking ──成功──► ok
                                   ├──部分能力可用──► degraded
                                   └──失败──► error
任意状态 ──禁用──► disabled
```

### 3.5 政策

```text
unverified ──人工核对──► verified ──超过复核周期──► stale
verified/stale ──API diff 冲突──► conflict（转人工）
```

### 3.6 交付物

```text
requested ──生成──► generated ──校验和──► verified ──写盘/打印──► delivered
任意 ──失败──► failed（保留原因码）
```

### 3.7 Agent Run 与审批

```text
queued ──► running ──不需要写──► succeeded
                 │
                 ├──需要写──► waiting_approval ──批准──► running ──► succeeded
                 │                         └──拒绝──► rejected（Run 终止）
                 ├──失败──► failed
                 └──用户取消──► cancelled
```

规则：
- 只有 `running` 能发起工具调用；`waiting_approval` 只能读。
- 审批状态：`pending → approved / rejected / expired`；过期需重新发起。
- 任何 `succeeded` 的写操作必须有对应 `Approval` 与审计事件。

```text
            ├──► core/render
            └──► core/integrations ──► 外部 API
```

禁止：
- `web` → `store/security` 直接调用（必须经 Platform API / 命令总线）。
- `agent` → `domains/store` 直接调用（必须经 Tool Registry / 命令总线）。
- `domains` → `integrations` 直接依赖（走端口接口 + 注入）。
- `render` → 任何 IO。
- `apps` → 任何 SQL/加密实现。
- 循环依赖（domain A ↔ domain B）：用应用服务编排，不互相 import。

> 以上规则由 `XC-01` 架构测试自动阻断，不靠评审记忆；检查项见 `08 §3.4`。

## 6. 模块状态维护

- 每个模块在 `06` 有一行状态：`SPEC / DEV / TEST / DONE / REL`。
- 进入 `DEV` 前必须有：模块规格（`02`）、接口契约（`04`）、验收清单。
- 进入 `DONE` 前必须满足 `02 §1` 通用 DoD。
- 进入 `REL` 前必须有：E2E、性能预算、可访问性、发布清单。
- 任何模块新增行为，先改 `01/02/04`，再改代码；文档不是事后补的。
