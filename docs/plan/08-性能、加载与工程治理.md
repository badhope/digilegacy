# 08 · 性能、加载与工程治理

> 本文件回答四个问题：**平台在真实数据量下快不快、页面怎么加载、模块怎么不腐化、工程怎么持续管。**
> 与 `05` 的关系：`05` 是质量门禁总表；本文件展开性能、加载、模块化、工程治理与高级项目管理。
> 与 `06` 的关系：新增工作包 `WP-49`~`WP-53`，总计增加 6.5 人日。

## 1. 性能策略

### 1.1 六条关键路径

| 路径 | 用户感知 | 主要瓶颈 | 设计原则 |
|---|---|---|---|
| 冷启动 → 概览 | 打开就能看到待办 | JS 包体、会话/锁定状态、首屏查询 | 静态壳先出；路由分块；概览单查询；次要数据空闲加载 |
| 资产列表 1000 条 | 搜索、筛选、翻页不卡 | 全量查询、客户端过滤、DOM 过多 | 游标分页；服务端筛选；虚拟列表；详情预取 |
| 资产详情 | 点开即见 | 关联查询 N+1、报告正文过大 | 单对象 + 摘要；标签懒加载；重内容不进详情 |
| 报告/导出 | 生成不冻结界面 | 同步渲染、PDF/ZIP 阻塞 | 异步任务；进度；可离开页面；完成后下载 |
| Agent Run | 能看到步骤、能取消、能审批 | 工具串行、事件洪泛、无预算 | 当前 1.5s 静默轮询；后续 SSE；增量时间线；轮次/工具/成本上限 |
| SSE 断线恢复 | 刷新不丢状态 | 无事件 ID、全量刷新 | `Last-Event-ID` 补发；按实体失效；不全页重载 |

当前落地（M3-G）：审批恢复已走 durable `jobs` + `jobs.get`；Web 运行详情对 `queued/running/waiting_approval` 每 1.5 秒静默刷新，页面隐藏暂停，只更新当前运行，不整页 reload。SSE 仍作为后续优化，不作为当前依赖。

| 层 | 指标 | 预算 | 测量方式 |
|---|---|---|---|
| Web | 首屏可交互 | ≤ 1.5 s | 参考机，冷缓存 |
| Web | 首次数据可见 | ≤ 1.0 s | 概览首个查询完成 |

| Web | 布局偏移 CLS | ≤ 0.1 | 骨架尺寸与最终一致 |
| API | 读 p95 | ≤ 150 ms | 本地/自托管，1000 资产 |

### 1.3 设计原则（写死）

1. **先测量再优化。** 没有基准数据的“优化”不算优化。
2. **列表永远分页。** 不允许一次拉全量资产、审计、运行记录。
3. **筛选/排序在服务端。** 前端只做展示与轻量本地过滤，不在 1000 条上全量计算。
4. **避免 N+1。** 列表查询按页聚合；详情按需加载；仓储提供批量方法。
5. **读模型分离。** 报告/概览用只读聚合，不在事务里拼大对象。
6. **长任务异步化。** 报告、PDF、ZIP、批量导入走任务表 + 进度，不占请求线程。
7. **有界并发。** LLM、邮件、导出、工具调用都有并发上限与队列；满了返回 `RATE_LIMITED`。
8. **超时与退避。** 所有外部调用有超时、重试上限、熔断；不允许无限等待。
9. **缓存只缓存可重建的东西。** 密钥、明文凭据、完整报告正文不进 localStorage/查询缓存。
10. **按实体失效。** SSE `entity.changed` 精确失效，不整页刷新、不全量 re-fetch。
11. **大对象不进首屏。** 政策全文、报告正文、审计全量都不进首屏 payload。
12. **前端不阻塞主线程。** 大 diff、CSV 解析、复杂计算放 Web Worker 或后端。

### 1.4 性能优先级

| 级别 | 路径 | 策略 |
|---|---|---|
| P0 | 首屏、资产列表、报告生成、Agent Run、SSE 恢复 | 预算硬阻断；每里程碑实测 |
| P1 | 资产详情、搜索、规划、交付预览 | 预算软阻断；回归 >20% 必须解释 |
| P2 | 设置、审计导出、政策候选、关于 | 不阻断发布，但不能卡住 P0 |

> 优化顺序：先 P0 的查询与 payload，再 P1 的缓存/预取，最后 P2；不允许用 P2 优化挤占 P0。

### 1.5 数据规模与索引

**基准数据集（CI 生成，不入库）：**

| 数据 | 基线 | 压力 |
|---|---|---|
| 资产 | 1,000 | 10,000 |
| 继承人/执行人 | 20 | 100 |
| 审计事件 | 10,000 | 100,000 |
| Agent Run | 500 | 5,000 |
| 交付物导出 | 1,000 | 10,000 |

| 政策候选 | 100 | 1,000 |

**必须有索引的查询：**

| 表 | 索引 | 用途 |
|---|---|---|
| `digital_assets` | `(status, updated_at)` | 列表默认排序/筛选 |
| `digital_assets` | `(platform_id, status)` | 按平台筛选 |
| `audit_log` | `(created_at)` | 最近活动/导出 |
| `agent_run_log` | `(status, started_at)` | 运行列表/活跃 Run |
| `agent_approvals` | `(status, created_at)` | 审批队列 |
| `deliverable_exports` | `(status, created_at)` | 导出任务 |
| `policy_candidates` | `(status, updated_at)` | 政策候选 |
| `connections` | `(kind, status)` | 连接健康 |
| `check_in_log` | `(created_at)` | 签到时间线 |

**查询规则：**

- 禁止 `SELECT *` 进列表接口；DTO 明确字段。
- 禁止深 `OFFSET` 分页；用 `(updated_at, id)` 游标。
- 列表默认 `limit=50`，最大 200；超过拒绝 `INVALID_ARGS`。
- 聚合查询必须 `EXPLAIN QUERY PLAN` 审查；无索引的全表扫描 CI 标记。
- 迁移/导入分批提交，单批 ≤ 500 行；失败回滚并保留备份。

### 1.6 缓存策略

| 层 | 缓存什么 | 不缓存什么 | 失效 |
|---|---|---|---|
| HTTP 静态 | JS/CSS/字体/图标 | — | 文件名 hash，`immutable` |
| HTTP API GET | 可重建的只读资源 | 凭据、报告正文、审计明细 | `ETag`/`If-None-Match`；敏感资源 `no-store` |
| 查询层 | 列表/详情/概览 | 密钥、明文、完整导出 | 实体键 + SSE + 写后失效 |
| 本地草稿 | 未提交表单 | 已提交敏感数据 | 提交成功即清；锁定即清 |
| 多标签页 | 失效广播 | 业务数据副本 | `BroadcastChannel` 通知，不复制状态 |

**规则：**

- 锁定/退出时清空敏感查询缓存与草稿；`423` 统一进锁定态。
- 写命令服务端 ack 后才改缓存；只有草稿允许乐观更新。
- 缓存键按实体：`['asset', id]`、`['assets', filters]`、`['run', id]`，不把整页塞进一个 key。
- 不允许把“页面状态”与“服务端状态”混在同一个 store。

### 1.7 测量与门禁

| 项 | 做法 |
|---|---|
| 基准数据 | `tools/perf/seed` 生成 1k/10k 资产、10k 审计、500 Run |
| Rust 基准 | `criterion`：解锁、列表查询、报告渲染、迁移 |
| 前端基准 | Vitest bench + Playwright trace：首屏、路由、列表、Run 时间线 |
| API 基准 | `oha`/`wrk` 脚本：读/写 p95、SSE 并发 |
| 基线 | 每个里程碑保存 JSON 报告；对比上一里程碑 |
| 门禁 | G13 性能冒烟；G17 加载预算；回归 >20% 阻断 |
| 报告 | 里程碑性能一页：预算/实测/趋势/豁免 |

## 2. 加载策略

### 2.1 启动顺序

```text
0. 静态壳（HTML/CSS/字体）           < 300 ms
1. 会话/安全状态（并行，不阻塞壳）    < 100 ms（本地）
2. 当前路由 chunk（懒加载）           < 300 ms
3. 概览首个查询（关键数据）           < 300 ms
4. 次要查询（待办/活动/审批）         空闲加载
5. SSE 连接（首屏渲染后）            首屏后 1 s 内
```

**规则：**

- 不允许“先等会话 → 再等路由 → 再等数据”的串行瀑布；会话与路由并行。
- 首屏只等“能看见 + 能操作”的最小数据；审批、最近活动、图表可后到。
- 首屏渲染前不建立 SSE；避免事件洪泛拖慢首屏。
- 路由 chunk 失败可重试一次；版本不匹配提示刷新，不静默白屏。

### 2.2 路由与代码加载

| 对象 | 策略 |
|---|---|
| 路由 | 每个主入口独立 chunk；`/assets/:id` 与 `/deliverables/:id` 共享实体组件 |
| 首屏 | 只加载 Overview + 壳 + 设计令牌；不预载资产/自动化 |
| 预取 | 空闲时预取最可能访问的 2 个入口；hover 资产行预取详情 |
| 第三方 | 图表、PDF 预览、diff 查看器按需加载；不进首屏 |
| i18n | 按域拆分；首屏只载当前语言公共 + overview 键 |
| 失败 | chunk 加载失败重试；连续失败显示“刷新/诊断”，不白屏 |
| 版本 | 新版本部署后旧 chunk 404 → 提示刷新；不强制丢草稿 |

**目标：** 首屏 chunk ≤ 200 KB；`DashboardView` 462 KB 这类巨石必须拆成 Overview + 图表 + 审批 + 活动。

### 2.3 数据加载

**查询层规则：**

- 每个实体一个 query key；列表 key 含筛选条件；详情 key 只含 ID。
- `staleTime`：概览 30 s、列表 30 s、详情 60 s、Run 进行中 0（靠 SSE）。
- 翻页用 `useInfiniteQuery`/游标；保留上一页数据，避免闪白。
- 请求可取消；路由切换/筛选变化取消旧请求，避免竞态覆盖。
- 后台刷新不显示全屏 loading；只显示细进度条/局部骨架。
- 写操作：服务端 ack 后失效对应 key；不先改列表再等失败回滚。
- 幂等：创建/导出带 `Idempotency-Key`；重复点击不产生重复对象。

**按页面：**

| 页面 | 首屏加载 | 后置加载 | 不加载 |
|---|---|---|---|
| 概览 | 状态、待办、审批数 | 最近活动、趋势图 | 资产全量、报告正文 |
| 资产列表 | 第一页 50 条、总数 | 后续页、筛选项 | 全部资产、全部凭据 |
| 资产详情 | 对象 + 关键摘要 | 关联交付物、审计 | 完整报告 HTML |
| 规划 | 持有人、继承人、触发摘要 | 签到历史、发件箱 | 资产明细 |
| 交付 | 交付物列表/当前版本 | 预览正文、导出记录 | 全部历史版本 |
| 自动化 | 活跃 Run、待审批数 | 历史 Run、工具目录 | 全量事件日志 |
| 设置 | 当前标签数据 | 其他标签 | 全量审计 |

**长任务（报告/PDF/ZIP/批量导入）：**

- 提交返回 `jobId`；页面显示进度与“可离开”。
- 进度走 SSE `job.updated` 或轮询 `GET /api/v1/jobs/{id}`；失败可重试。
- 完成后只取下载链接/哈希，不把文件塞进 JSON。
- 用户离开页面任务继续；重进从任务状态恢复。

**Agent Run：**

- 事件增量追加；时间线虚拟列表；500 事件 ≤300 ms。
- 首事件前显示“规划中”，不显示假进度。
- 取消在下一轮工具前生效；取消后保留已产生的只读结果。
- 审批卡先到先展示；不等待整个 Run 结束。

### 2.4 状态与骨架

| 状态 | 表现 | 要求 |
|---|---|---|
| 首屏加载 | 壳 + 骨架，尺寸接近最终 | 不整页转圈；CLS ≤0.1 |
| 局部加载 | 区块骨架/细进度条 | 不遮住已可用区域 |
| 空 | 解释 + 主操作 | 不写“暂无数据” |
| 部分成功 | 已成功部分可用 + 失败项列表 | 不整页报错 |
| 错误 | 错误码 + 重试 + 诊断 | 不丢用户输入 |
| 锁定 | 全局遮罩 + 解锁 | 敏感数据不渲染 |
| 离线 | 顶栏标记 + 只读提示 | 写操作禁用/排队草稿 |

**规则：**

- 加载超过 300 ms 才显示骨架/进度；300 ms 内不闪。
- 骨架尺寸、行高、列宽与最终一致；避免布局跳动。
- 不允许全页 spinner 覆盖已加载的壳与导航。
- 错误边界按 feature 隔离；单页失败不白屏。

### 2.5 离线与多标签

- 离线默认**只读**：可看最近快照、可编辑草稿；提交写操作需恢复连接。
- 草稿只存本地加密/非敏感字段；锁定/退出清除。
- 多标签用 `BroadcastChannel` 广播失效与锁定；不复制业务状态。
- 只有一个标签页持有 SSE/写队列（leader）；其他标签只读缓存并接收广播。
- 版本更新/锁定/退出时，所有标签同步提示。

### 2.6 加载验收

| 场景 | 通过标准 |
|---|---|
| 冷启动 | 首屏 ≤1.5 s；首数据 ≤1 s；无全页 spinner |
| 路由切换 | ≤300 ms；有骨架；不白屏 |
| 1000 条列表 | 首屏 ≤200 ms；滚动不掉帧；筛选不整页转圈 |
| 详情 | 打开 ≤300 ms；重内容后置 |
| 报告/导出 | 提交 ≤1 s 返回 jobId；不冻结 UI；可离开 |
| Agent Run | 首事件 ≤2 s；500 事件时间线 ≤300 ms；取消 ≤1 轮 |
| SSE 断线 | ≤5 s 恢复；不丢已读事件 |
| 弱网 | 壳可用；错误可重试；不无限转圈 |

## 3. 模块化

### 3.1 模块化单体，不做微服务

本期是**模块化单体**：一个 Rust 核心进程 + 一个 Web 控制台 + 可选桌面壳。  
拆模块的目的是**边界清晰、可测试、可替换**，不是拆成多个网络服务。

```text
apps/*            适配器：web/desktop/cli/server/mcp
core/interfaces   入口层：CommandBus / HTTP / CLI / MCP
core/agent        Agent Runtime / Tool Registry / Approval
core/domains      领域服务：资产/规划/交付/审核/触发
core/render       纯渲染：DTO → HTML/文本
core/store        存储：SQLite / 迁移 / 仓储
core/security     加密 / 密钥 / 恢复 / 备份
core/integrations 外部端口：LLM / 邮件 / 政策 / 心跳
core/foundation   契约 / 错误 / 审计 / 生命周期
```

**为什么不做微服务：** 单用户/自托管、数据强一致、部署要简单；微服务会带来网络失败、分布式事务、运维成本，收益为零。

### 3.2 依赖边界

| 层 | 允许依赖 | 禁止依赖 |
|---|---|---|
| `apps/web` | `platformClient`、设计令牌、共享 UI | 核心 Rust、SQLite、密钥、业务规则 |
| `apps/desktop` | Web 构建产物、壳 API | 业务逻辑、第二套页面、独立数据路径 |
| `apps/cli` / `apps/mcp` | Platform API / Tool API | 直接连库、绕过 CommandBus |
| `core/interfaces` | CommandBus、应用服务 | 直接写 SQL、直接操作 UI |
| `core/agent` | Tool Registry、CommandBus | 直接调 domains/store、直接发邮件 |
| `core/domains` | store/security/render/ports | 互相直接 import、依赖 integrations 实现 |
| `core/integrations` | ports、security、store | 反向依赖 domains 业务规则 |
| `core/render` | DTO、模板、设计令牌 | 读库、写文件、发网络请求 |
| `core/store` | security（字段加密） | 依赖 domains/UI |
| `core/security` | store（密文） | 依赖 domains/UI |
| `core/foundation` | contracts/errors/audit | 依赖具体业务域 |

**跨域协作：** 用应用服务编排；A 域不能 import B 域的 repo，也不能直接改 B 域的表。  
**共享内核：** 只有 `foundation` 放跨域契约；禁止 `utils/` 变成第二个业务层。  
**前端：** `features` 不互相 import；跨页复用下沉到 `entities/shared`；`shared` 不放业务规则。

### 3.3 模块接口规范

每个核心模块固定结构：

```text
modules/<name>/
  mod.rs        # 显式导出，禁止 pub use *
  model.rs      # 实体/值对象
  service.rs    # 用例入口（对 CommandBus 暴露）
  ports.rs      # 外部依赖 trait（可注入 mock）
  repo.rs       # 私有仓储，不对外导出
  tests/        # 单元 + 集成
```

规则：

- 模块对外只暴露 `service` 的用例与 `ports` 的 trait；`repo` 不跨模块可见。
- 禁止 `pub use *`；公共 API 必须显式列出。
- 生产文件 ≤800 行、函数 ≤60 行作为**预警线**；超过必须拆或写 ADR 说明。  
  `db.rs` 2,312 行、`ProfileView` 1,498 行属于必须拆的对象。
- 禁止无票据的 `#[allow(dead_code)]`；死代码要么删，要么登记技术债。
- 新模块必须同时有：规格（`02`）、契约（`04`）、验收、负责人、缺口登记。

### 3.4 架构测试（自动阻断）

| 检查 | 工具 | 失败即阻断 |
|---|---|---|
| 循环依赖 | `cargo-modules`/自定义 dep graph | 是 |
| 禁止 import：domain→web、domain→integrations 实现、apps→store | `tools/arch-check` | 是 |
| SQL 只在 store：`rusqlite::Connection` 不出 store | `rg` + 白名单 | 是 |
| `invoke(` 只在 `platform/` 客户端 | ESLint 自定义规则 | 是 |
| `fetch(` 只在 `platform/` 客户端 | ESLint 自定义规则 | 是 |
| feature 互相 import | `dependency-cruiser` | 是 |
| 路由 chunk >200 KB | 构建脚本 | 是 |
| i18n 缺键/重复键 | 生成器 | 是 |
| 模块文件 >800 行 / 函数 >60 行 | `tools/arch-check` 预警 | 里程碑评审 |
| 无 ADR 的不可逆变更 | PR 模板 + 检查 | 是 |

### 3.5 模块生命周期

`SPEC → DEV → TEST → DONE → REL`，与 `06 §8` 一致。

| 阶段 | 入口条件 | 出口条件 |
|---|---|---|
| SPEC | 需求登记、边界清楚 | `02` 规格 + `04` 契约 + 验收清单 |
| DEV | 契约冻结、测试数据可用 | 代码 + 单测 + 架构检查通过 |
| TEST | 集成环境可用 | 集成/契约/E2E + 性能/安全回归 |
| DONE | 全部门禁绿 | DoD 全满足、文档更新、缺口清零/延期 |
| REL | 发布清单签字 | 安装/升级/回滚演练通过 |

## 4. 软件工程管理

### 4.1 开发流程

- **Trunk-based**：`main` 始终可发布；分支生命周期 ≤2 天；大改拆 PR。
- **PR 大小**：目标 ≤400 行变更；超过必须拆或说明。
- **提交信息**：Conventional Commits；一个提交一件事。
- **合并门槛**：G01–G07 + 相关测试 + 架构检查；`main` 禁止直接 push。
- **发布**：里程碑打 tag；hotfix 从 tag 拉分支，合并回 `main`。
- **环境**：本地 dev → CI 临时库 → 演示站 → 自托管/生产；配置走环境变量，密钥不进仓库。

### 4.2 DoR / DoD

**Definition of Ready（进入开发前）：**

1. 模块 ID、目标、边界、非目标；
2. 命令/API/工具契约；
3. 数据与迁移影响；
4. 验收标准与测试数据；
5. 性能/安全/隐私影响；
6. 依赖与风险。

**Definition of Done：** `02 §1` 的 16 项 + 本文件 §1–§3 的性能/加载/边界要求。

### 4.3 代码评审

| 类型 | 要求 |
|---|---|
| 普通 PR | 至少 1 次独立评审；作者不能自批 |
| 安全/数据/迁移/契约 | 两次评审：技术 + 安全/数据视角；人类最终签字 |
| Agent 生成代码 | 必须附测试证据与契约 diff；不得自动合并 |
| 评审时限 | 24 h 内首轮反馈；阻塞项必须写原因 |
| 评审清单 | 边界、错误、并发、事务、日志、测试、性能、可访问性 |

### 4.4 ADR / RFC

| 文档 | 何时写 | 内容 |
|---|---|---|
| ADR | 不可逆决策：schema、加密、契约版本、依赖引入、部署形态 | 背景/决策/备选/后果/回滚 |
| RFC | 跨模块、跨客户端、影响 >2 个模块 | 目标/方案/接口/迁移/测试/风险 |
| 决策日志 | 每个里程碑 | 决策、日期、替代方案、影响 |

规则：

- 没有 ADR 的不可逆变更不合并。
- ADR 一经接受不修改；被替代时新建 ADR，旧文标记 `superseded`。
- RFC 讨论结论必须落到 `06` 变更单或 ADR，不允许只留在聊天记录。

### 4.5 变更、弃用与开关

- **变更控制**：走 `06 §9`；影响契约/数据/安全必须附 ADR。
- **API 版本**：`/api/v1`；只做加法；破坏性变更升 `v2`。
- **弃用**：字段/命令标记 `deprecated`，至少保留 1 个 minor；文档写替代；到期移除。
- **Feature Flag**：高风险功能默认关；有 owner、到期日；最多保留 2 个里程碑，之后删。
- **紧急修复**：S0/S1 可走 hotfix，但 24 h 内补测试/复盘/缺口登记。

### 4.6 依赖与技术债

| 项 | 规则 |
|---|---|
| 锁文件 | `Cargo.lock`、`package-lock.json` 必须提交 |
| 新增依赖 | 必须写 ADR：用途、替代、许可证、维护状态、体积 |
| 许可证 | 允许 MIT/Apache-2.0/BSD/ISC；GPL/AGPL 需明确批准 |
| 漏洞 SLA | high/critical 7 天内修；medium 30 天；low 季度 |
| 升级节奏 | 每季度一次批量升级；安全补丁随时 |
| 技术债 | 每个里程碑 ≥10% 容量还债；登记利息与到期 |
| 禁止 | 无测试的“临时方案”、无票据的 `allow(dead_code)`、无 owner 的 TODO |

### 4.7 工程指标

| 指标 | 目标 | 频率 |
|---|---|---|
| 变更 Lead Time | ≤3 天 | 每周 |
| 变更失败率 | ≤15% | 每周 |
| MTTR | ≤1 天 | 事件后 |
| 逃逸缺陷 | 0 个/里程碑（S0/S1） | 里程碑 |
| 性能回归 | 0 个 >20% | 每次 CI |
| 模块边界违规 | 0 | 每次 CI |
| 缺口燃尽 | 里程碑前 OPEN 清零/延期 | 每周 |
| 覆盖率 | 达 `05 §1.2` | 每次 CI |
| Bus factor | 每个关键模块 ≥2 种接手路径（文档+测试+AI 上下文） | 每月 |

### 4.8 SLO 与运行手册

| 项 | 目标 | 测量 |
|---|---|---|
| 可用性（使用时段） | ≥99.5% | 健康检查/启动失败日志；本地统计 |
| P0 读 p95 | ≤150 ms | API/页面基准 |
| P0 写 p95 | ≤300 ms | 不含长任务 |
| Agent 审批/审计 | 100% | 每次写操作有 Approval + 审计 |
| 备份成功率 | 100% | 每日备份记录 |
| 恢复演练 | 每季度 ≥1 次 | 演练记录/耗时 |
| RPO / RTO | ≤24 h / ≤1 h | 备份与恢复演练 |
| S0 事件 | 0 | 事件台账 |

**运行手册必须覆盖：** 启动/停止、备份/恢复、锁定/解锁、磁盘满、端口冲突、SSE 不工作、Agent 卡住、导出失败、回滚、诊断包导出。  
**原则：** 没有运行手册的功能不算可发布；没有演练的恢复不算可靠。

### 4.9 事件与复盘

| 级别 | 定义 | 响应 |
|---|---|---|
| S0 | 数据丢失、密钥泄漏、越权写 | 立即停发版，24 h 内复盘 |
| S1 | 核心不可用、迁移失败、导出损坏 | 当天修复，48 h 复盘 |
| S2 | 部分功能降级、性能严重超预算 | 下一迭代修复 |
| S3 | 文案/样式/轻微体验 | 排期 |

复盘只写事实、影响、根因、行动项、负责人、到期；行动项进 `06` 缺口，不写“注意一下”。

### 4.10 AI 辅助工程

- AI 可以写代码、测试、文档、迁移脚本；**人类对合并与发布负责**。
- AI 生成代码必须：有测试、过架构检查、附契约 diff；安全/数据变更人类签字。
- AI 评审不能替代人类对敏感模块的最终签字；AI 结论必须可复核。
- 提示词/上下文不包含真实密钥、完整凭据、未脱敏用户数据。
- 生成物（客户端/桩/schema）不允许手改；改源 `contracts/` 再生成。

## 5. 项目高级管理

### 5.1 阶段门禁

沿用 `M0`~`M6`，但增加工程治理门禁：

| 里程碑 | 新增门禁 |
|---|---|
| M0 | 架构测试可跑；ADR/PR/DoR 模板可用；性能基准脚本可跑 |
| M1 | 迁移/备份/审计有回滚演练 |
| M2 | 领域模块无跨域 repo 访问；契约测试全绿 |
| M3 | API 分页/ETag/限流/超时实测；CLI/MCP 不绕过命令总线 |
| M4 | 首屏/路由/列表/骨架达预算；无全页阻塞；加载验收通过 |
| M5 | Agent 预算/取消/审批/审计实测；外部调用有超时/退避 |
| M6 | SLO/运行手册/故障演练/性能趋势报告完成 |

### 5.2 计划与控制

- **WIP 限制**：同时进行的工作包 ≤3；先完成再开新。
- **缓冲**：每个里程碑 15% 时间缓冲；缓冲消耗 >50% 预警。
- **关键路径**：`WP-01 → WP-02 → WP-49 → WP-08 → WP-11 → WP-15 → WP-20 → WP-29 → WP-35 → WP-39 → WP-43 → WP-47`。
- **燃尽**：按 WP 完成度与缺口 OPEN 数双轴燃尽；不看“感觉完成”。
- **信心**：每个 WP 标绿/黄/红；关键路径有红则里程碑红。
- **范围冻结**：里程碑开始后新增需求进下一里程碑；S0 例外。
- **决策**：每周一次决策清单；未决事项进风险，不默认通过。

### 5.3 治理节奏

| 周期 | 事项 | 产出 |
|---|---|---|
| 每日 | 构建绿、状态看板、新缺口 | 一页状态 |
| 每周 | 进度/缺口/风险/性能趋势/决策清单 | 周报 + 决策记录 |
| 每月 | 架构评审、依赖升级、技术债、Bus factor | 架构纪要 + ADR |
| 每里程碑 | 门禁评审、安全评审、发布/演示、复盘 | 门禁签字 + 复盘 |

### 5.4 停止规则（防止硬撑）

出现任一条，暂停新功能，先处理：

1. 连续 2 个里程碑延期 >20%；
2. 质量门禁红 >2 周；
3. 性能回归 >20% 未修复；
4. S0 安全/数据事件未闭环；
5. 关键模块 Bus factor =1 且无接手文档。
