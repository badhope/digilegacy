# 05 · 质量与交付工程

> 目标：每个模块“做完”有客观证据；每个版本“能发”有可回滚路径。
> 性能、加载、模块化、工程治理的展开见 `08-性能、加载与工程治理.md`；本文件保留门禁总表。

## 1. 测试策略

### 1.1 测试金字塔

| 层 | 工具 | 覆盖对象 | 目标 |
|---|---|---|---|
| Rust 单元 | `cargo test` | 加密、状态机、校验、渲染纯函数 | 核心算法边界全覆盖 |
| Rust 集成 | `cargo test` + 临时库 | 仓储、迁移、备份、导入、审计链 | 真实 SQLite 行为 |
| 契约 | 自定义 `contracts:check` | 命令/错误/权限/传输 | 七方集合一致 |
| 架构 | `tools/arch-check` + dependency-cruiser | 依赖方向/循环/禁止 import/跨域 repo | 0 违规 |
| 前端单元 | Vitest（node 环境） | stores、utils、i18n、api | 纯逻辑快 |
| 前端组件 | Vitest + jsdom | 表单、抽屉、状态组件 | 状态与交互 |
| E2E | Playwright | 5 入口主路径 | 用户能走通 |
| 视觉 | Playwright screenshot | 关键页面/明暗 | 无意外像素变化 |
| 可访问性 | axe-core + 键盘脚本 | 页面与浮层 | 0 critical/serious |
| 性能 | 自定义 bench | 启动、列表、报告、搜索 | 达预算 |
| 加载 | Playwright + Chrome trace | 首屏、路由、骨架、长任务、SSE 恢复 | 达 `08 §2` 预算 |
| 安全 | audit + secret scan + fuzz | 依赖、密钥、解析器 | 0 高危；解析器不崩 |
| 模糊 | `cargo-fuzz` | 备份导入、政策补丁、HTML 渲染 | 不 panic、不越界 |

### 1.2 覆盖率门槛

| 范围 | 指标 | 门槛 |
|---|---|---|
| Rust `security/` | 行覆盖 | ≥ 85% |
| Rust `store/` | 行覆盖 | ≥ 75% |
| Rust `domains/` | 行覆盖 | ≥ 70% |
| Rust `agent/`（Runtime + Tool Registry） | 行覆盖 | ≥ 80% |
| Rust `render/` | 行覆盖 | ≥ 80% |
| 前端 | 分支 | ≥ 80% |
| 前端 | 语句 | ≥ 85% |
| 命令契约 | 命令覆盖 | 100% |

覆盖率报告必须显式 include 全部源码；未加载文件按 0% 计入分母（防假绿灯）。

### 1.3 测试提速

- 纯逻辑用 `environment: node`；只有组件用 jsdom。
- jsdom 环境复用（`pool: 'vmThreads'` 或 `isolate: false`），避免每文件重建。
- E2E 与视觉分离；视觉基线只在 UI 变更时更新。
- 目标：单测全量 ≤180 秒（当前 548 秒）。

## 5. 安全工程

### 5.1 威胁模型

| 资产 | 威胁 | 控制 |
|---|---|---|
| 凭据/密码 | 本地恶意软件、备份被拷 | 字段加密、整库加密、备份认证、DPAPI |
| 主密码/DEK | 内存转储、日志泄漏 | Zeroizing、无日志、锁定清零 |
| 恢复份额 | 打印件被拍照、份额丢失 | 3-of-5、校验说明、演练 |
| API Key | 明文 HTTP、日志、导出 | HTTPS-only、加密存储、日志打码、导出排除 |
| 导出物 | XSS、路径穿越、外部资源 | 全量转义、CSP meta、ZIP 路径净化 |
| HTTP 端口 | 未授权读写、密钥外泄 | 默认回环、token、deny-list、写白名单 |
| LLM 输入 | Prompt injection（政策文本/工具结果） | 工具结果视为不可信；无写工具自动执行；系统提示约束；输出需人工确认 |
| Agent 工具 | 越权调用、自动批准、隐藏写操作 | 工具白名单 + 权限档 + 审批 + 审计 + 运行预算 |
| 政策 API | 恶意/被篡改响应 | 签名/哈希校验、候选制、人工批准 |
| 更新通道 | 供应链劫持 | 签名清单、TLS、回滚、分通道 |
| 依赖 | 供应链漏洞 | audit、锁定版本、最小依赖、定期升级 |

### 5.2 安全评审清单（每个模块）

1. 信任边界画了吗？（webview/Rust/网络/文件）
2. 敏感数据进了日志/错误/诊断包吗？
3. 输入校验在边界层吗？长度/枚举/格式/路径。
4. 输出转义了吗？（HTML/ZIP/CLI）
5. 失败是 fail-closed 还是 fail-open？
6. 新增依赖有必要吗？许可证/维护状态？
7. 新增命令的权限档正确吗？
8. 审计事件写了吗？

### 5.3 模糊测试目标

- 备份导入（JSON/加密载荷）
- 平台补丁（JSON）
- 政策 API 响应（JSON）
- HTML 渲染（超长/控制字符/闭合标签）
- CLI 参数（超长/异常 Unicode）

要求：不 panic、不越界、不写库、错误可读。

## 6. 发布与更新

### 6.1 版本

- 应用版本：SemVer（`MAJOR.MINOR.PATCH`）。
- Schema 版本：独立整数（v9 起）。
- 命令契约版本：manifest `version`，破坏性变更升 MAJOR。
- 模板版本：每类交付物独立（`report-v3`、`guide-v2`）。

### 6.2 渠道

| 渠道 | 用途 | 更新策略 |
|---|---|---|
| `stable` | 普通用户 | 手动检查 + 后台静默下载，重启安装 |
| `beta` | 自愿测试 | 自动检查，显式提示 |
| `dev` | 开发 | 本地构建，不签名 |

### 6.3 签名与更新

- Windows 安装包与可执行文件签名：Azure Trusted Signing 或 EV 证书。
- 更新清单签名（Ed25519）；客户端内置公钥；拒绝未签名清单。
- 更新流程：检查 → 下载 → 验签 → 安装 → 失败回滚到上一版。
- 灰度：按 5% → 25% → 100% 放量；异常停止。
- 卸载：默认保留数据；显式“同时删除数据”需二次确认。

### 6.4 发布清单

1. 全部门禁绿；
2. 版本号/schema/模板版本同步；
3. 安装包签名验证；
4. 干净虚拟机安装 → 首次运行 → 设置主密码 → 导出 → 卸载；
5. 升级路径测试（v0.6.0 → 新版本，旧备份导入）；
6. 更新回滚演练；
7. Release Notes（用户语言，不写内部术语）；
8. 哈希与签名公开；
9. 性能/加载基线报告归档（预算/实测/趋势/豁免）。

## 7. 文档工程

| 文档 | 内容 | 更新时机 |
|---|---|---|
| `docs/POSITIONING.md` | 定位、三句话、卖点排序、禁用表述 | 每次营销/文案变更 |
| `docs/ARCHITECTURE.md` | 模块、依赖、数据流 | 模块变更 |
| `docs/VERIFICATION.md` | 本轮实跑命令、结果、未验证项 | 每个里程碑 |
| `docs/CHANGELOG.md` | Keep a Changelog | 每次发布 |
| `docs/USER-GUIDE.md` | 用户操作、常见问题 | 功能变更 |
| `docs/THREAT-MODEL.md` | 威胁与控制 | 安全变更 |

规则：
- 数字（命令数/测试数/平台数/页面数）由脚本从源码推导，与文档比对，不一致 CI 红。
- 文档不允许出现“即将支持/预留”，未实现的功能只进缺口台账。
- README 不复制站点全文，只留摘要 + 链接。

## 8. 可观测性（无遥测）

| 项 | 做法 |
|---|---|
| 日志 | 结构化、按级别、滚动保留 14 天、0600；不含敏感数据 |
| 审计 | `audit_log` 哈希链；可校验、可导出 |
| 诊断包 | 用户主动导出：版本、schema、最近错误码、审计摘要、连接状态；不含凭据/PII |
| 崩溃 | 本地崩溃日志；下次启动提示“导出诊断包” |
| 指标 | 只在本地统计（启动耗时、报告耗时），不上传 |
| 隐私 | 无账号、无遥测、无远程上报；文档明确写 |

> SLO、运行手册、容量模型与故障演练见 `08 §4.8/§5.1`。
