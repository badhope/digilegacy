# 09 · M2-B 政策库与交付物模块

> 目的：把 M2-B 从“又一个页面”收成平台模块：数据、用例、契约、入口、前端与验收一一对应。
> 状态：**已完成**（2026-11-19，`./tools/verify.sh` 全绿，日志 `/tmp/digilegacy-verify-m2b.log`）。

## 1. 模块边界

| 模块 | 职责 | 不负责 | 代码位置 |
|---|---|---|---|
| POL-01 政策数据 | 152 条平台政策、20 字段、分类 | 资产事实、用户隐私 | `content/policies/platforms.json` |
| POL-02 政策领域 | seed、分页、分类、关键词、详情、名称匹配 | HTTP、页面 | `core/domains/src/policy.rs` |
| POL-03 溯源 | `policy_provenance` 独立表；默认 `unverified` | 伪造“已核实” | schema v10 |
| DEL-01 交付用例 | 四类交付物组装、HTML 渲染、文件写入、Job 落库 | 页面样式 | `core/application/src/deliver.rs` |
| DEL-02 下载边界 | canonical 路径校验、`text/html` 附件 | 任意文件读取 | `apps/server` + `Application::read_export` |
| WEB-01 政策视图 | 资产二级标签、搜索/分类/游标、详情、来源链接 | 第二个后端 | `web/src/features/policies/PoliciesView.vue` |
| WEB-02 交付视图 | 四类生成、结果、下载、会话记录 | 重复 API 调用逻辑 | `web/src/features/deliverables/DeliverablesView.vue` |

## 2. 契约与入口

| 命令 | 权限 | HTTP | CLI | MCP |
|---|---|---|---|---|
| `policies.list` | read | `GET /api/v1/policies` | `policies list` | 是 |
| `policies.get` | read | `GET /api/v1/policies/{id}` | `policies get` | 是 |
| `deliver.export` | draft | `POST /api/v1/deliverables/export` | `deliver export` | 是 |

- 所有入口落到同一个 `Application::dispatch`，没有第二套业务逻辑。
- `deliver.export` 输出 `jobId/status/progress/fileName/downloadUrl/generatedAt`，契约 `job.output` 已扩展。
- 下载路由不在命令总线内，只做“已成功 Job → 受控文件”的传输；路径必须落在导出根目录。

## 3. 数据与迁移

- schema v10，27 表；新增 `policies`、`policy_provenance` 与两个索引。
- 旧 `platforms` / `policy_overrides` 保留，仅为资产 FK 兼容；政策读取不依赖旧桌面结构。
- 种子只在 `policies` 空表时执行，`INSERT OR REPLACE`；重复启动不重复写。
- 152 条全部 `unverified`；`source_url` 取 `official_policy_url`，`note` 取 `data_source`。
- 法律模板 `content/legal/templates.json` 四类：继承声明、平台申请、数字遗嘱条款、继承人分配协议。

## 4. 前端使用逻辑

- **政策库不是第 6 个主导航**。它是资产域的二级标签：`/assets`（资产清单）与 `/policies`（平台政策）。
- 资产详情页在平台明确时提供“平台政策”按钮，带 `?q=` 进入政策库，避免用户重新输入。
- 政策列表：服务端 `q/category/limit/cursor`；默认 100，加载更多；分类来自服务端，不在前端硬编码。
- 政策详情：材料列表、流程、风险、变现路径、官方来源、申请表、溯源状态；未核实明确显示。
- 交付页：四类卡片各自调用 `deliver.export`；成功后显示文件名、下载链接与会话记录；失败显示平台错误。
- 界面去重：政策库不复制资产列表；交付页不重复导航；设置仍是全局工具区。

## 5. 性能与加载

| 项 | 策略 | 当前基线 |
|---|---|---|
| 政策列表 | 服务端分页 + 分类筛选 + 关键词；不一次拉 152 条全文 | 首屏 100 条，加载更多 |
| 政策详情 | 单条读取；左列表轻量字段 | 点击后一次 `policies.get` |
| 交付导出 | 同步生成，数据量有界；Job 落库供下载 | 当前数据量 < 2 s |
| 下载 | 流式返回文件字节；路径校验 | `text/html` |
| 前端包体 | 路由懒加载；政策/交付各自 chunk | 政策 7.01 KB raw，交付 3.43 KB raw |
| 总预算 | 总 gzip ≤ 110 KB | 87.30 KB |

超出上述边界时，先登记 `06` 缺口，再决定是否改异步 Job/SSE。

## 6. 软件工程管理

- **契约先行**：命令、工具、schema、错误码只在 `contracts/` 改；再跑 `node tools/generate.mjs`。
- **架构门禁**：`node tools/arch-check.mjs` 校验 15 命令 / 12 工具 / 21 schema / 19 错误码。
- **模块边界**：`apps/* → core/application → core/domains/store/security`；页面不得直接访问 SQLite。
- **测试分层**：领域测试（数据/分页/溯源）、用例测试（导出/下载/审计）、入口测试（HTTP/CLI/MCP）、Web 测试（路由/渲染）。
- **变更控制**：新增命令必须同时有 schema、权限、审计策略、至少一个入口测试；否则不合入。
- **缺口登记**：未完成项写入 `06`，状态只能是 `OPEN/DEFERRED/CLOSED`，不接受口头待办。
